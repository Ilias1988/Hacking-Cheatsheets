> **Примечание к шаблону:** поля в квадратных скобках оставлены с исходными именами для подстановки ваших данных; числовые значения и суммы — примеры. ASCII-схемы сохранены с английскими подписями: Critical — критический, High — высокий, Medium — средний, Low — низкий; Impact — последствия, Likelihood — вероятность. Внешние ограждения Markdown, содержащие вложенные примеры, расширены до четырёх обратных кавычек для корректного отображения. Команды и payloads не изменены.

> На схемах Overall Risk Rating — общий уровень риска; Risk Reduction — снижение риска; Investment Required — необходимые затраты; Before Assessment — до оценки; After Remediation — после устранения; Target — целевое состояние. На одностраничной схеме TOP 3 RISKS — три главных риска; Potential data breach affecting X customers — возможная утечка данных X клиентов; Regulatory fines up to $X — штрафы регуляторов до $X; Business disruption risk of X days — риск простоя бизнеса в течение X дней; Estimated cost — оценка стоимости каждой меры; RECOMMENDED INVESTMENT — рекомендуемые затраты; EXPECTED RISK REDUCTION — ожидаемое снижение риска. Значения 70/100, суммы, проценты и отраслевые ориентиры условны и требуют обоснования для реальной организации.

## 📋 Структура резюме для руководства

````markdown
# РЕЗЮМЕ ОЦЕНКИ БЕЗОПАСНОСТИ ДЛЯ РУКОВОДСТВА

**Заказчик:** [Company Name]
**Тип оценки:** [Penetration Test / Security Audit / Vulnerability Assessment]
**Дата:** [Assessment Period]
**Гриф:** КОНФИДЕНЦИАЛЬНО

---

## 1. Цель и границы проверки

[Your Company] привлечена для проведения [type of assessment] в [Company Name]:
[describe scope in business terms]. Цель — оценить состояние безопасности
и выявить возможные риски для деятельности организации.

**В границы проверки вошли:**
- [Business system 1]
- [Business system 2]
- [Network/Infrastructure]

---

## 2. Общая оценка безопасности

│                                                     │
│            OVERALL RISK RATING: HIGH                │
│                                                     │

│                                                     │
│    Immediate attention required                     │
│                                                     │

| Уровень | Определение |
|--------|------------|
| 🔴 **Критический** | Необходимы немедленные действия. Высокая вероятность компрометации. |
| 🟠 **Высокий** | Существенные уязвимости. Необходимо срочное устранение. |
| 🟡 **Средний** | Умеренный риск. Запланировать устранение в течение 30–60 дней. |
````

## 💡 Советы по подготовке текста для руководства

### Что следует делать ✅
```
✓ Начинать с последствий для бизнеса
✓ Использовать простой язык без профессионального жаргона
✓ Приводить понятный анализ затрат и пользы
✓ Давать рекомендации, которые можно выполнить
✓ Ограничивать объём максимум 2–3 страницами
✓ Использовать диаграммы, графики и таблицы
✓ Показывать отдачу от вложений в безопасность (ROI)
✓ Сравнивать с отраслевыми ориентирами
```

### Чего следует избегать ❌
```
✗ Не использовать техническую терминологию (CVE, CVSS и т. п.)
✗ Не перечислять все проблемы; выделять критические
✗ Не перегружать техническими подробностями
✗ Не забывать указывать затраты и сроки
✗ Не увеличивать объём без необходимости
✗ Не запугивать без предложения решений
```
