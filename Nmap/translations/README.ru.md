<a id="-introduction"></a>
## 🎯 Введение

> **Уточнение к терминам:** определения «stealth» и «обход» в оригинале не гарантируют незаметность или успех. Тип сканирования и его результат зависят от полномочий, ОС, фильтрации и условий сети. TCP Connect также не гарантирует доступность каждого сервиса.

**Nmap** (Network Mapper) — свободная утилита с открытым исходным кодом для исследования сетей и аудита безопасности. Это широко используемый инструмент сетевого сканирования.

<a id="key-features"></a>
### Основные возможности

| Возможность | Описание |
| --------- | ------------- |
| **Обнаружение узлов** | Поиск доступных узлов сети |
| **Сканирование портов** | Определение открытых портов и сервисов |
| **Определение версий** | Определение версий сервисов |
| **Определение ОС** | Определение операционных систем |
| **Скрипты NSE** | Поиск и эксплуатация уязвимостей |
| **Форматы вывода** | XML, grepable и обычный текстовый вывод |

<a id="port-states"></a>
### Состояния портов

> **Примечание об оформлении:** вертикальная черта внутри двух значений таблицы экранирована по [правилам GitHub Markdown](https://github.github.com/gfm/#example-200), чтобы сохранить ячейки. Отображаемые значения остаются open|filtered и closed|filtered.

| Состояние | Описание |
| ------- | ------------- |
| `open` | Приложение принимает соединения |
| `closed` | Порт доступен, но приложение его не прослушивает |
| `filtered` | Nmap не может определить, открыт ли порт (фильтрация) |
| `unfiltered` | Порт доступен, но неизвестно, открыт он или закрыт |
| `open\|filtered` | Нельзя определить, открыт порт или фильтруется |
| `closed\|filtered` | Нельзя определить, закрыт порт или фильтруется |

<a id="-basic-syntax"></a>
## ⌨️ Базовый синтаксис

<a id="general-syntax"></a>
### Общий синтаксис
```bash
nmap [Scan Type] [Options] {target}
```

<a id="quick-start-examples"></a>
### Примеры для быстрого старта
```bash
# Базовое сканирование
nmap 192.168.1.1

# Сканировать несколько узлов
nmap 192.168.1.1 192.168.1.2 192.168.1.3

# Сканировать диапазон
nmap 192.168.1.1-254

# Сканировать всю подсеть
nmap 192.168.1.0/24

# Сканировать цели из файла
nmap -iL targets.txt
```

<a id="-target-specification"></a>
## 🎯 Указание целей

<a id="single-targets"></a>
### Отдельные цели
```bash
# IP-адрес
nmap 192.168.1.1

# Имя узла
nmap scanme.nmap.org

# Домен
nmap example.com
```

<a id="multiple-targets"></a>
### Несколько целей
```bash
# Цели через пробел
nmap 192.168.1.1 192.168.1.2 192.168.1.3

# Диапазон
nmap 192.168.1.1-100

# Запись CIDR
nmap 192.168.1.0/24

# Подстановочный символ
nmap 192.168.1.*

# Диапазон октетов
nmap 192.168.0-255.1-254

# Смешанное указание целей
nmap 192.168.1.0/24 10.0.0.1
```

<a id="input-from-file"></a>
### Ввод из файла
```bash
# Читать из файла
nmap -iL targets.txt

# targets.txt:
# 192.168.1.1
# 192.168.1.0/24
# scanme.nmap.org
```

<a id="exclude-targets"></a>
### Исключение целей
```bash
# Исключить один узел
nmap 192.168.1.0/24 --exclude 192.168.1.1

# Исключить цели из файла
nmap 192.168.1.0/24 --excludefile exclude.txt
```

<a id="random-targets"></a>
### Случайные цели
```bash
# Сканировать случайные узлы (для исследования)
nmap -iR 100
```

<a id="-host-discovery"></a>
## 🔎 Обнаружение узлов

<a id="discovery-options"></a>
### Параметры обнаружения

| Параметр | Описание |
| -------- | ------------- |
| `-sL` | Сканирование списком: только перечисление целей |
| `-sn` | Обнаружение узлов без сканирования портов |
| `-Pn` | Пропустить обнаружение, считать все узлы доступными |
| `-PS` | Проверка доступности через TCP SYN |
| `-PA` | Проверка доступности через TCP ACK |
| `-PU` | Проверка доступности через UDP |
| `-PE` | Проверка через ICMP Echo |
| `-PP` | Проверка через ICMP Timestamp |
| `-PM` | Проверка через ICMP Address Mask |
| `-PO` | Проверка с помощью IP-протоколов |
| `-PR` | Проверка через ARP (локальная сеть) |

<a id="ping-scan-no-port-scan"></a>
### Обнаружение узлов без сканирования портов
```bash
# Только обнаружить доступные узлы
nmap -sn 192.168.1.0/24

# Обнаружение узлов по списку
nmap -sn -iL hosts.txt
```

<a id="skip-host-discovery"></a>
### Пропуск обнаружения узлов
```bash
# Сканировать все указанные узлы без предварительной проверки доступности
nmap -Pn 192.168.1.1

# Полезно, когда:
# - Узлы блокируют ICMP
# - Сканирование идёт через межсетевой экран
```

<a id="tcp-synack-ping"></a>
### Обнаружение с помощью TCP SYN/ACK
```bash
# Проверить доступность через TCP SYN на порт 80
nmap -PS80 192.168.1.1

# Проверить доступность через TCP ACK на порт 80
nmap -PA80 192.168.1.1

# Несколько портов
nmap -PS22,80,443 192.168.1.1
```

<a id="udp-ping"></a>
### Обнаружение с помощью UDP
```bash
# Проверка доступности через UDP
nmap -PU53 192.168.1.1

# Несколько портов
nmap -PU53,161 192.168.1.1
```

<a id="icmp-ping"></a>
### Обнаружение с помощью ICMP
```bash
# ICMP Echo
nmap -PE 192.168.1.1

# ICMP Timestamp
nmap -PP 192.168.1.1

# ICMP Address Mask
nmap -PM 192.168.1.1
```

<a id="arp-ping-local-network"></a>
### Обнаружение с помощью ARP (локальная сеть)
```bash
# ARP-сканирование (быстро в локальной сети)
nmap -PR 192.168.1.0/24

# Только ARP-обнаружение
nmap -sn -PR 192.168.1.0/24
```

<a id="disable-dns-resolution"></a>
### Отключение разрешения DNS-имён
```bash
# Без разрешения DNS-имён (быстрее)
nmap -n 192.168.1.1

# Всегда разрешать DNS-имена
nmap -R 192.168.1.1
```

<a id="-port-scanning-techniques"></a>
## 🔌 Методы сканирования портов

<a id="scan-types-overview"></a>
### Обзор типов сканирования

| Параметр | Название | Описание |
| -------- | ------ | ------------- |
| `-sS` | SYN-сканирование | Полуоткрытое сканирование (по умолчанию, требует root) |
| `-sT` | TCP Connect | Полное TCP-соединение (root не требуется) |
| `-sU` | Сканирование UDP | Сканировать UDP-порты |
| `-sA` | ACK-сканирование | Исследовать правила межсетевого экрана |
| `-sW` | Window-сканирование | Аналог ACK, использует поле окна TCP |
| `-sM` | Сканирование Maimon | Проверка с флагами FIN/ACK |
| `-sN` | NULL-сканирование | Флаги не установлены |
| `-sF` | FIN-сканирование | Установлен флаг FIN |
| `-sX` | Xmas-сканирование | Флаги FIN, PSH и URG |

<a id="syn-stealth-scan-default"></a>
### Полуоткрытое SYN-сканирование (по умолчанию)
```bash
# Наиболее распространённый тип сканирования (требует root)
sudo nmap -sS 192.168.1.1

# Не завершает трёхэтапное установление TCP-соединения
# Быстро и относительно малозаметно
```

<a id="tcp-connect-scan"></a>
### Сканирование с полным TCP-соединением
```bash
# Полное TCP-соединение
nmap -sT 192.168.1.1

# Root не требуется
# Заметнее; в оригинале заявлена универсальная работоспособность (см. уточнение)
```

<a id="udp-scan"></a>
### Сканирование UDP
```bash
# Сканировать UDP-порты
sudo nmap -sU 192.168.1.1

# UDP-сканирование МЕДЛЕННОЕ
# Совместить с определением версий
sudo nmap -sU -sV 192.168.1.1

# Распространённые UDP-порты
sudo nmap -sU -p 53,67,68,69,123,161,500 192.168.1.1
```

<a id="combined-tcpudp"></a>
### Совместное сканирование TCP/UDP
```bash
# Сканировать TCP и UDP
sudo nmap -sS -sU 192.168.1.1

# Определённые порты
sudo nmap -sS -sU -p T:80,443,U:53,161 192.168.1.1
```

<a id="null-fin-xmas-scans"></a>
### Сканирование NULL, FIN и Xmas
```bash
# NULL-сканирование (без флагов)
sudo nmap -sN 192.168.1.1

# FIN-сканирование (только флаг FIN)
sudo nmap -sF 192.168.1.1

# Xmas-сканирование (FIN, PSH, URG)
sudo nmap -sX 192.168.1.1

# Подходит для:
# - Обхода межсетевых экранов без отслеживания состояния
# - В оригинале отмечено, что метод не работает с Windows
```

<a id="ack-scan"></a>
### ACK-сканирование
```bash
# Исследовать правила межсетевого экрана
sudo nmap -sA 192.168.1.1

# Определить:
# - Какие порты фильтруются
# - Правила межсетевого экрана
# Возвращает: unfiltered или filtered
```

<a id="window-scan"></a>
### Window-сканирование
```bash
# Аналогично ACK-сканированию
sudo nmap -sW 192.168.1.1

# Использует размер окна TCP для определения состояния
```

<a id="idlezombie-scan"></a>
### Сканирование Idle с промежуточным узлом zombie
```bash
# Для скрытности используется промежуточный узел zombie
sudo nmap -sI zombie_host 192.168.1.1

# В оригинале указано, что ваш IP не обращается к цели (см. уточнение)
# Требуется подходящий узел zombie
```

<a id="-port-specification"></a>
## 🎚️ Указание портов

<a id="port-options"></a>
### Параметры портов

| Параметр | Описание |
| -------- | ------------- |
| `-p <port>` | Сканировать указанные порты |
| `-p-` | Сканировать все 65535 портов |
| `-p 1-1000` | Сканировать диапазон портов |
| `--top-ports <n>` | Сканировать N наиболее распространённых портов |
| `-F` | Быстрое сканирование (100 распространённых портов) |
| `-r` | Сканировать порты последовательно |

<a id="specific-ports"></a>
### Определённые порты
```bash
# Один порт
nmap -p 80 192.168.1.1

# Несколько портов
nmap -p 80,443,22 192.168.1.1

# Диапазон портов
nmap -p 1-1000 192.168.1.1

# Все порты
nmap -p- 192.168.1.1

# Смешанное указание целей
nmap -p 22,80,443,1000-2000 192.168.1.1
```

<a id="port-by-protocol"></a>
### Порты с учётом протокола

> **Уточнение:** префиксы T:/U: выбирают списки портов, но не включают соответствующий тип сканирования. Для UDP и совместного TCP/UDP нужны соответствующие параметры сканирования; см. [официальное руководство](https://nmap.org/book/man-port-specification.html). Исходные команды сохранены.
```bash
# TCP-порты
nmap -p T:80,443 192.168.1.1

# UDP-порты
nmap -p U:53,161 192.168.1.1

# Оба протокола
nmap -p T:80,443,U:53 192.168.1.1
```

<a id="top-ports"></a>
### Наиболее распространённые порты
```bash
# 100 распространённых портов (быстро)
nmap -F 192.168.1.1

# 10 распространённых портов
nmap --top-ports 10 192.168.1.1

# 1000 распространённых портов (по умолчанию)
nmap --top-ports 1000 192.168.1.1
```

<a id="-service--version-detection"></a>
## 🔬 Определение сервисов и версий

<a id="version-detection-options"></a>
### Параметры определения версий

| Параметр | Описание |
| -------- | ------------- |
| `-sV` | Определение версий |
| `--version-intensity <0-9>` | Интенсивность проверок |
| `--version-light` | Облегчённое определение версий (интенсивность 2) |
| `--version-all` | Попробовать все проверки (интенсивность 9) |
| `--version-trace` | Отладка определения версий |

<a id="basic-version-detection"></a>
### Базовое определение версий
```bash
# Определить версии сервисов
nmap -sV 192.168.1.1

# Пример типичного вывода:
# PORT    STATE SERVICE VERSION
# 22/tcp  open  ssh     OpenSSH 7.9
# 80/tcp  open  http    Apache httpd 2.4.38
```

<a id="version-intensity"></a>
### Интенсивность определения версий
```bash
# Облегчённое сканирование (быстрее)
nmap -sV --version-light 192.168.1.1

# Все проверки (тщательнее)
nmap -sV --version-all 192.168.1.1

# Заданная интенсивность (0-9)
nmap -sV --version-intensity 5 192.168.1.1
```

<a id="-os-detection"></a>
## 💻 Определение ОС

<a id="os-detection-options"></a>
### Параметры определения ОС

| Параметр | Описание |
| -------- | ------------- |
| `-O` | Включить определение ОС |
| `--osscan-limit` | Определять ОС только у подходящих узлов |
| `--osscan-guess` | Настойчивее подбирать предположение об ОС |
| `--max-os-tries` | Максимум попыток определения ОС |

<a id="basic-os-detection"></a>
### Базовое определение ОС
```bash
# Определить ОС (требует root)
sudo nmap -O 192.168.1.1

# Пример вывода:
# Running: Linux 3.X|4.X
# OS CPE: cpe:/o:linux:linux_kernel:3
# OS details: Linux 3.10 - 4.11
```

<a id="aggressive-os-guessing"></a>
### Более настойчивое предположение об ОС
```bash
# Более настойчивый подбор предположения
sudo nmap -O --osscan-guess 192.168.1.1
```

<a id="aggressive-scan--a"></a>
### Комплексное сканирование (-A)
```bash
# Включить определение ОС, версий, скрипты и traceroute
sudo nmap -A 192.168.1.1

# Эквивалентно: -O -sV -sC --traceroute
```

<a id="-timing--performance"></a>
## ⏱️ Временные параметры и производительность

<a id="timing-templates"></a>
### Шаблоны временных параметров

| Параметр | Название | Описание |
| -------- | ------ | ------------- |
| `-T0` | Paranoid (параноидальный) | Обход IDS, очень медленно |
| `-T1` | Sneaky (скрытный) | Обход IDS, медленно |
| `-T2` | Polite (вежливый) | Меньшая нагрузка на канал, медленнее |
| `-T3` | Normal (обычный) | Временные параметры по умолчанию |
| `-T4` | Aggressive (агрессивный) | Быстро, для надёжной сети |
| `-T5` | Insane (предельный) | Очень быстро, возможен пропуск портов |

<a id="usage"></a>
### Применение
```bash
# Медленно и относительно малозаметно
nmap -T1 192.168.1.1

# Обычные параметры (по умолчанию)
nmap -T3 192.168.1.1

# Быстро
nmap -T4 192.168.1.1

# Очень быстро (локальная сеть)
nmap -T5 192.168.1.1
```

<a id="fine-grained-timing"></a>
### Точная настройка временных параметров

| Параметр | Описание |
| -------- | ------------- |
| `--min-rate <n>` | Минимальное число пакетов в секунду |
| `--max-rate <n>` | Максимальное число пакетов в секунду |
| `--min-parallelism <n>` | Минимум параллельных проверок |
| `--max-parallelism <n>` | Максимум параллельных проверок |
| `--min-hostgroup <n>` | Минимум узлов в параллельной группе |
| `--max-hostgroup <n>` | Максимум узлов в параллельной группе |
| `--host-timeout <time>` | Прекратить работу с узлом по истечении времени |
| `--scan-delay <time>` | Задержка между проверками |
| `--max-retries <n>` | Максимум повторов проверки |

```bash
# Отправлять не менее 1000 пакетов в секунду
nmap --min-rate 1000 192.168.1.0/24

# Не более 100 пакетов в секунду (снижение скорости)
nmap --max-rate 100 192.168.1.1

# Прекратить работу с узлом через 30 минут
nmap --host-timeout 30m 192.168.1.0/24

# Задержка между проверками
nmap --scan-delay 1s 192.168.1.1
```

<a id="-nse-scripts"></a>
## 📜 Скрипты NSE

> **Уточнение категорий:** safe не означает гарантию отсутствия побочных эффектов; некоторые default-скрипты также относятся к intrusive. Пояснения см. в [документации NSE](https://nmap.org/book/nse-usage.html). Названия категорий и исходные примеры сохранены.

<a id="script-categories"></a>
### Категории скриптов

| Категория | Описание |
| ---------- | ------------- |
| `auth` | Работа с учётными данными и обход аутентификации |
| `broadcast` | Обнаружение узлов широковещательными запросами |
| `brute` | Перебор учётных данных |
| `default` | Скрипты по умолчанию (-sC) |
| `discovery` | Исследование сервисов |
| `dos` | Отказ в обслуживании |
| `exploit` | Эксплуатация уязвимостей |
| `external` | Запросы к внешним сервисам |
| `fuzzer` | Фаззинг |
| `intrusive` | Могут вызвать сбой сервисов |
| `malware` | Обнаружение вредоносного ПО |
| `safe` | Скрипты категории safe |
| `version` | Определение версий |
| `vuln` | Обнаружение уязвимостей |

<a id="script-options"></a>
### Параметры скриптов

| Параметр | Описание |
| -------- | ------------- |

| `--script-args <args>` | Аргументы скриптов |
| `--script-updatedb` | Обновить базу скриптов |
| `--script-help <script>` | Справка по скрипту |

<a id="-output-formats"></a>
## 📄 Форматы вывода

> **Уточнение вывода:** -oA записывает три формата — normal, XML и grepable; -oG считается устаревшим. Параметр --open также включает потенциально открытые состояния open|filtered и unfiltered, а не только open. См. [официальное руководство](https://nmap.org/book/man-output.html).

<a id="output-options"></a>
### Параметры вывода

| Параметр | Описание |
| -------- | ------------- |
| `-oN <file>` | Обычный текстовый вывод |
| `-oX <file>` | Вывод XML |
| `-oG <file>` | Вывод grepable |
| `-oA <basename>` | Все форматы из примера |
| `-oS <file>` | Стилизованный вывод Script kiddie |

<a id="save-output"></a>
### Сохранение результатов
```bash
# Обычный текстовый вывод
nmap -oN scan.txt 192.168.1.1

# Вывод XML (для инструментов)
nmap -oX scan.xml 192.168.1.1

# Вывод grepable
nmap -oG scan.gnmap 192.168.1.1

# Все указанные форматы одновременно
nmap -oA scan 192.168.1.1
# Создаёт: scan.nmap, scan.xml, scan.gnmap
```

<a id="verbosity--debugging"></a>
### Подробность вывода и отладка

| Параметр | Описание |
| -------- | ------------- |
| `-v` | Увеличить подробность вывода |
| `-vv` | Ещё более подробный вывод |
| `-d` | Режим отладки |
| `-dd` | Более подробная отладка |
| `--reason` | Показать причину определения состояния порта |
| `--open` | Показывать только открытые порты (упрощение оригинала) |
| `--packet-trace` | Показать все пакеты |

```bash
# Подробный вывод
nmap -v 192.168.1.1

# Очень подробный вывод
nmap -vv 192.168.1.1

# Показать только открытые порты (упрощение оригинала)
nmap --open 192.168.1.1

# Показать причину
nmap --reason 192.168.1.1
```

<a id="-firewallids-evasion"></a>
## 🛡️ Обход межсетевых экранов и IDS

<a id="evasion-techniques"></a>
### Методы обхода обнаружения

| Параметр | Описание |
| -------- | ------------- |
| `-f` | Фрагментировать пакеты |
| `--mtu <size>` | Задать размер MTU |
| `-D <decoys>` | Использовать ложные источники |
| `-S <IP>` | Подменить IP-адрес источника |
| `--source-port <port>` | Подменить порт источника |
| `--data-length <n>` | Добавить случайные данные |
| `--randomize-hosts` | Случайный порядок узлов |
| `--spoof-mac <mac>` | Подменить MAC-адрес |
| `--badsum` | Отправить неверные контрольные суммы |

<a id="packet-fragmentation"></a>
### Фрагментация пакетов
```bash
# Фрагментировать пакеты
nmap -f 192.168.1.1

# Заданный MTU
nmap --mtu 16 192.168.1.1
```

<a id="decoys"></a>
### Ложные источники (decoys)
```bash
# Использовать ложные источники
nmap -D decoy1,decoy2,ME 192.168.1.1

# Случайные ложные источники
nmap -D RND:5 192.168.1.1
```

<a id="source-ipport-spoofing"></a>
### Подмена IP-адреса и порта источника
```bash
# Подменить IP-адрес источника
nmap -S 192.168.1.100 -e eth0 192.168.1.1

# Подменить порт источника (часто разрешаемые порты)
nmap --source-port 53 192.168.1.1
nmap --source-port 80 192.168.1.1
```

<a id="mac-spoofing"></a>
### Подмена MAC-адреса
```bash
# Случайный MAC-адрес
nmap --spoof-mac 0 192.168.1.1

# Указанный производитель
nmap --spoof-mac Apple 192.168.1.1

# Указанный MAC-адрес
nmap --spoof-mac 00:11:22:33:44:55 192.168.1.1
```

<a id="data-padding"></a>
### Дополнение данных
```bash
# Добавить случайные данные в пакеты
nmap --data-length 25 192.168.1.1
```

<a id="-tips--best-practices"></a>
## 💡 Советы и рекомендуемые практики

<a id="performance-tips"></a>
### Советы по производительности

1. **Использовать SYN-сканирование (по умолчанию)**
   ```bash
   # Требует root, но обычно быстрее
   sudo nmap -sS 192.168.1.1
   ```

2. **Сначала ограничить диапазон портов**
   ```bash
   # Начать с наиболее распространённых портов
   nmap --top-ports 100 192.168.1.1
   ```

3. **Увеличить скорость для локальных сетей**
   ```bash
   nmap -T5 --min-rate 5000 192.168.1.0/24
   ```

<a id="accuracy-tips"></a>
### Советы по точности

1. **Использовать несколько типов сканирования**
   ```bash
   # TCP и UDP
   sudo nmap -sS -sU -sV 192.168.1.1
   ```

2. **Увеличить число повторов для ненадёжных сетей**
   ```bash
   nmap --max-retries 3 192.168.1.1
   ```

<a id="legal-considerations"></a>
### Правовые аспекты

> ⚠️ **ВАЖНО:** Сканируйте только собственные сети или сети, на проверку которых получено разрешение.

- ✅ Собственные сети
- ✅ Лабораторные среды
- ✅ Разрешённые тесты на проникновение
- ❌ Случайные узлы интернета
- ❌ Сети без разрешения владельца
