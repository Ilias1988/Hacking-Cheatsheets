# Security Policy

## Reporting a security concern

Do not open a public issue for exposed credentials, personal data, malicious files, unsafe download links, or instructions that could cause unintended harm when copied as written.

Use GitHub's private vulnerability reporting feature from the repository's **Security** tab. Include:

- the affected file and section;
- why the content is unsafe or misleading;
- a safe reproduction in an isolated lab, when relevant;
- a proposed maintained source or remediation.

Do not include real credentials, client information, live targets, weaponized malware, or data obtained without authorization.

## Scope

Reports about the repository itself, its automation, exposed secrets, dependency or workflow risks, and materially unsafe documentation are in scope. General vulnerability disclosures for third-party tools should be sent to the relevant upstream maintainer.

## Supported content

The `main` branch is the only supported version. Commands are educational references and must be validated against the stated tool version and official documentation before use.
