# 🔧 x64dbg — справочник по отладчику Windows

<!-- language-home-navigation -->
[🏠 Русская главная страница](../../README.ru.md) • [🌐 Languages](../../README.md#-available-languages)

[← Русское оглавление](../../README.ru.md) · [Английский оригинал](../README.md)

> **Уточнение к командам.** В [официальной справке](https://help.x64dbg.com/en/latest/commands/debug-control/run.html) g и r — синонимы run, а не команды простого перехода или присваивания регистру. Для просмотра адреса предусмотрен disasm; [mov/set](https://help.x64dbg.com/en/latest/commands/general-purpose/mov.html) задаёт переменную. Поэтому goto, r reg=val и /s, /x, /p из оригинала нельзя считать подтверждённым универсальным синтаксисом. Команды оставлены дословно. Названия меню и сочетания клавиш также зависят от выпуска и настроек; схема CPU показывает Disassembly (дизассемблер), Registers (регистры), Hex Dump (дамп) и Stack (стек). Надпись в логотипе означает «отладчик Windows x64/x32».

> **О точках останова.** У [bp](https://help.x64dbg.com/en/latest/commands/breakpoint-control/SetBPX.html) второй аргумент — имя точки, а третий — тип, не условие и не счётчик. [Условия и логирование](https://help.x64dbg.com/en/latest/introduction/ConditionalBreakpoint.html) настраиваются отдельно. В [bph](https://help.x64dbg.com/en/latest/commands/breakpoint-control/SetHardwareBreakpoint.html) r означает чтение и запись, размер 8 доступен только в x64, а адрес должен быть выровнен. [bpm](https://help.x64dbg.com/en/latest/commands/breakpoint-control/SetMemoryBPX.html) отслеживает весь регион памяти через PAGE_GUARD, а не только указанный байт.

> **О сценариях.** [find](https://help.x64dbg.com/en/latest/commands/searching/find.html) возвращает абсолютный виртуальный адрес в $result; прибавление его к исходному адресу в примере не является универсальным корректным продвижением поиска. Байты 8B EC обозначают MOV EBP, ESP; PUSH EBP имеет байт 55. Изменение ESP/RSP само по себе не выполняет полную операцию PUSH/POP. Исходные примеры и их строки сохранены. В [синтаксисе команд](https://help.x64dbg.com/en/latest/commands/) точка с запятой разделяет команды вне кавычек. [Парсер сценариев](https://github.com/x64dbg/x64dbg/blob/development/src/dbg/simplescript.cpp) принимает ; в начале строки как комментарий, но поясняющие хвосты после ; в строках примера не следует считать обычными inline-комментариями.

<a id="-what-is-x64dbg"></a>
## 🎯 Что такое x64dbg

**x64dbg** — открытый отладчик x64/x32 для Windows, развивающий идеи OllyDbg и предлагающий современные возможности:

- 🔍 **Отладка в пользовательском режиме** — отладка приложений Windows
- 🦠 **Анализ вредоносного ПО** — исследование подозрительных исполняемых файлов
- 💥 **Разработка эксплойтов** — исследование уязвимостей Windows
- 🔧 **Обратная разработка** — изучение поведения программ
- 🧩 **Плагины** — расширение возможностей отладчика

<a id="features"></a>
### Возможности

|Возможность|Описание|
|---------|-------------|
|**GUI**|Современный настраиваемый интерфейс|
|**Поддержка x64**|Полноценная 64-битная отладка|
|**Сценарии**|Встроенный язык сценариев|
|**Плагины**|Большой выбор плагинов|
|**Symbols (символы)**|Поддержка символов PDB|
|**Открытый код**|Бесплатный инструмент с активной разработкой|

## 🚀 Установка

<a id="download"></a>
### Загрузка

```
# Официальный сайт
https://x64dbg.com/

# Выпуски на GitHub
https://github.com/x64dbg/x64dbg/releases

# Скачать: snapshot_YYYY-MM-DD_HH-MM.zip
```

<a id="setup"></a>
### Настройка

```
1. Распаковать ZIP в постоянный каталог (например, C:\x64dbg\)
2. Запустить x96dbg.exe — средство выбора разрядности
   - x32dbg.exe → 32-bit: отладка программ соответствующей разрядности
   - x64dbg.exe → 64-bit: отладка программ соответствующей разрядности
3. При необходимости добавить в PATH или создать ярлыки
```

```
# Открыть исполняемый файл

# Открыть и запустить
Debug → Run (F9) — запустить

# Перезапустить отладку
Debug → Restart (Ctrl+F2) — перезапустить

```
# Вводите команды в командной строке внизу окна

# Перейти к выражению
g GetProcAddress

/s "password"

# Поиск шестнадцатеричных байтов
/x 90 90 90 90

# Поиск последовательности байтов

<a id="-breakpoints"></a>
## 🔴 Точки останова

<a id="software-breakpoints-int3"></a>
### Программные точки останова (INT3)

```
# Переключить точку останова по текущему адресу
F2

# Установить точку останова командой
bp 0x401000
bp kernel32.LoadLibraryA
bp module.function

# Установить условную точку останова (описание оригинала; см. уточнение)
bp 0x401000, "eax==0"
bp 0x401000, "[esp]==0x12345"

# Остановиться при загрузке модуля (пример оригинала)
bp $module(kernel32)
```

<a id="hardware-breakpoints"></a>
### Аппаратные точки останова

```
# Установить аппаратную точку останова (не более 4)
Щёлкнуть правой кнопкой → Breakpoint → Hardware → Execute (выполнение)
Щёлкнуть правой кнопкой → Breakpoint → Hardware → Access (доступ)
Щёлкнуть правой кнопкой → Breakpoint → Hardware → Write (запись)

# Через команду
bph 0x401000, x, 1    # Выполнение
bph 0x401000, r, 4    # Чтение (4 байта в оригинале; r отслеживает чтение и запись)
bph 0x401000, w, 4    # Запись (4 байта)

# Размеры: 1, 2, 4 или 8 байтов
```

<a id="memory-breakpoints"></a>
### Точки останова на доступ к памяти

```
# Остановиться при обращении к памяти
В дампе щёлкнуть правой кнопкой → Breakpoint → Memory → Access (доступ)
В дампе щёлкнуть правой кнопкой → Breakpoint → Memory → Write (запись)

# Через команду
bpm 0x401000, r       # Чтение
bpm 0x401000, w       # Запись
bpm 0x401000, x       # Выполнение
```

<a id="conditional-breakpoints"></a>
### Условные точки останова

```
# Остановиться при истинном условии (см. уточнение синтаксиса)
bp 0x401000, "eax==0"
bp 0x401000, "eax!=ebx"
bp 0x401000, "[esp+4]>0x100"
bp 0x401000, "byte:[eax]==0x90"

# Остановиться по числу срабатываний (см. уточнение)
bp 0x401000, "", 5    # При 5-м срабатывании (формулировка оригинала)

# Записывать в журнал без остановки
bplog 0x401000, "EAX={eax}, EBX={ebx}"
```

<a id="managing-breakpoints"></a>
### Управление точками останова

```
# Показать все точки останова
Окно Breakpoints (Alt+B), точки останова

# Удалить точку останова
bc 0x401000          # Удалить указанную точку
bc                   # Удалить все точки

# Включить или отключить
bd 0x401000          # Отключить
be 0x401000          # Включить

# Отключить все
bd *

# Включить все
be *
```

|Действие|Сочетание клавиш|Описание|

<a id="-memory-operations"></a>
## 🔍 Работа с памятью

<a id="memory-dump"></a>
### Дамп памяти

```
# Перейти к адресу в дампе
Щёлкнуть правой кнопкой → Follow in Dump → Address/Selection (адрес или выделение)

# Перейти к адресу в дампе
Ctrl+G (в окне дампа)

# Изменить представление дампа
Щёлкнуть правой кнопкой → Hex → [Byte/Word/Dword/Qword/ASCII/Unicode] (тип отображения)
```

<a id="memory-map"></a>
### Memory Map (карта памяти)

```
# Открыть Memory Map (карту памяти)
View → Memory Map (Alt+M) — карта памяти

# Показывает все области памяти:
- Address (адрес)
- Size (размер)
- Section (секция)
- Type (Image/Private/Mapped) — тип области
- Protection (Execute/Read/Write) — защита
- Module name (имя модуля)
```

<a id="search-memory"></a>
### Поиск в памяти

```
# Поиск через командную строку
/s "string"           # Строка ASCII
/s L"string"          # Строка Unicode
/x 90 90 90           # Шестнадцатеричные байты
/p "8B ?? 89"         # Последовательность с подстановочными символами

# Найти ссылки
Щёлкнуть правой кнопкой → Find references to → Selected Address (ссылки на выбранный адрес)

# Найти строки
Щёлкнуть правой кнопкой → Search for → All Strings (все строки)
```

<a id="memory-protection"></a>
### Защита памяти

```
# Просмотреть защиту
Memory Map → столбец Protection (защита)

# Распространённые атрибуты защиты
PAGE_EXECUTE_READ
PAGE_EXECUTE_READWRITE
PAGE_READONLY
PAGE_READWRITE
PAGE_NOACCESS
```

<a id="dump-memory"></a>
### Выгрузка памяти

```
# Выгрузить память в файл
В Memory Map щёлкнуть правой кнопкой → Dump Memory to File (выгрузить память в файл)

# Выгрузка с помощью плагинов
Plugins → OllyDumpEx → Dump (выгрузка через плагин)
```

<a id="modify-registers"></a>
### Изменение регистров

```
# Дважды щёлкните регистр для изменения
# Или щёлкните правой кнопкой → Modify Value (изменить значение)

# Через командную строку
r eax=0
r rax=0x12345678
r eip=0x401000
r zf=1            # Установить Zero Flag (флаг нуля)
```

<a id="important-flags"></a>
### Основные флаги

|Флаг|Название|Когда установлен|
|------|------|----------|
| ZF |Zero Flag (флаг нуля)|Результат равен нулю|
| CF |Carry Flag (флаг переноса)|Беззнаковое переполнение|
| SF |Sign Flag (флаг знака)|Результат отрицательный|
| OF |Overflow Flag (флаг переполнения)|Знаковое переполнение|
| DF |Direction Flag (флаг направления)|Направление строковых операций|
| TF |Trap Flag (флаг пошагового выполнения)|Пошаговое выполнение|

<a id="toggle-flags"></a>
### Переключение флагов

```
# Щёлкните букву флага в панели регистров
# Или используйте команды:
r zf=!zf         # Переключить Zero Flag (флаг нуля)
r cf=0           # Сбросить Carry Flag (флаг переноса)
r sf=1           # Установить Sign Flag (флаг знака)
```

## 📚 Анализ стека

<a id="stack-panel"></a>
### Панель стека

```
# Показывает содержимое стека со следующими полями:
- Address (адрес)
- Value (значение)
- Comments (комментарии, если доступны)

# Пункты контекстного меню:
- Follow DWORD in Disassembler (перейти по DWORD в дизассемблере)
- Follow DWORD in Dump (перейти по DWORD в дампе)
- Modify (изменить)
```

<a id="call-stack"></a>
### Call Stack (стек вызовов)

```
# Открыть Call Stack (стек вызовов)
View → Call Stack (Alt+K) — стек вызовов

# Показывает:
- Return Address (адрес возврата)
- From (вызывающая функция)
- To (вызываемая функция)
- Size (размер)
- Comment (комментарий)
```

<a id="stack-operations"></a>
### Операции со стеком

```
# Перейти к адресу стека
Щёлкнуть правой кнопкой → Follow DWORD in Stack (перейти по DWORD в стеке)

# Изменить значение в стеке
Щёлкнуть правой кнопкой → Modify → Edit (изменить значение)

# Имитация Push/Pop (изменяется только указатель стека)
r esp=esp-4      # Push (32-bit; изменяется только указатель)
r esp=esp+4      # Pop (32-bit; изменяется только указатель)
r rsp=rsp-8      # Push (64-bit; изменяется только указатель)
r rsp=rsp+8      # Pop (64-bit; изменяется только указатель)
```

<a id="stack-layout-32-bit-stdcall"></a>
### Устройство стека (32-битный stdcall)

```
[ESP]      → Return Address (адрес возврата)
[ESP+4]    → Arg1 (первый аргумент)
[ESP+8]    → Arg2 (второй аргумент)
[ESP+C]    → Arg3 (третий аргумент)
...

После PUSH EBP; MOV EBP, ESP:
[EBP]      → Saved EBP (сохранённый EBP)
[EBP+4]    → Return Address (адрес возврата)
[EBP+8]    → Arg1 (первый аргумент)
[EBP-4]    → Local1 (локальная переменная)
```

<a id="-scripting"></a>
## 📝 Сценарии

<a id="command-syntax"></a>
### Синтаксис команд

```
# Переменные
$var = 0x401000

# Сравнение
cmp eax, 0

# Условный переход
je label
jne label

# Метки
label:

# Комментарии
; Это комментарий в записи оригинала (см. уточнение синтаксиса)
```

<a id="basic-script"></a>
### Простой сценарий

```
; Сценарий поиска WinMain (иллюстрация оригинала)
mov $addr, 0x401000        ; Начальный адрес
loop:
  find $addr, "8B EC"       ; Найти PUSH EBP; MOV EBP, ESP (подпись оригинала; см. уточнение байтов)
  cmp $result, 0
  je notfound
  msg "Found at: {$result}"
  add $addr, $result
  add $addr, 1
  jmp loop
notfound:
  msg "Pattern not found"
ret
```

<a id="script-commands"></a>
### Команды сценариев

|Команда|Описание|
|---------|-------------|
| `msg "text"` |Показать сообщение|
| `log "text"` |Записать сообщение в журнал|
| `find addr, "pattern"` |Поиск последовательности байтов|
| `bp addr` |Установить точку останова|
| `bc addr` |Удалить точку останова|
| `sti` |Шаг с заходом|
| `sto` |Шаг без захода|
| `run` |Run (запуск)|
| `ret` |Возврат или остановка сценария|

<a id="run-script"></a>
### Запуск сценария

```
# Загрузить и запустить сценарий
Scripts → Run Script (запустить сценарий)

# Или через командную строку
scr "scriptfile.txt"
```

<a id="analysis-workflow"></a>
### Порядок анализа

```
1. Загрузить исполняемый файл → F3
2. Установить точку останова в точке входа → F2 в точке входа
3. Выполнить до точки останова → F9
4. Выполнять код пошагово → F7/F8
5. Изучить регистры и память → Panels (панели)
6. Установить дополнительные точки останова
7. Продолжить анализ
8. При необходимости изменить код → Space
9. Сохранить изменённый файл
```
