## 🎯 Введение

> **Версии и редакции:** оригинал смешивает старые меню Spider, Proxy → Options и Extender с более новыми интерфейсами. Имена меню и сочетания клавиш сохранены буквально; сверяйте их с [настройками установленной версии](https://portswigger.net/burp/documentation/desktop/settings). Цена $449/year, состав редакций и JRE 8+ — данные оригинала, а не актуальное предложение или требования; см. [системные требования](https://portswigger.net/burp/documentation/desktop/getting-started/system-requirements). Автоматизированные возможности зависят от редакции.

> **Горячие клавиши:** Ctrl+Shift+T в оригинале назначен двум действиям. Эти строки не означают, что оба назначения действуют одновременно; сочетания настраиваются в [UI settings / Hotkeys](https://portswigger.net/burp/documentation/desktop/settings/ui).

> **Пояснение эмблемы:** Web Application Security Testing Platform — платформа тестирования безопасности веб-приложений; ASCII-эмблема сохранена.

**Burp Suite** — комплексная платформа тестирования безопасности веб-приложений от PortSwigger, широко используемая при веб-пентестах.

<a id="first-launch-configuration"></a>
### Настройка при первом запуске

1. **Выбрать тип проекта**

2. **Настройка**

<a id="-proxy-configuration"></a>
## 🔌 Настройка прокси

<a id="browser-configuration"></a>
### Настройка браузера

<a id="manual-proxy-setup"></a>
#### Ручная настройка прокси

| Браузер | Где настраивается прокси |
| --------- | ------------------------ |
| Firefox | Settings → Network → Manual proxy |
| Chrome | Системный прокси или расширение |
| Safari | System Preferences → Network → Proxies |

**Прокси Burp по умолчанию:**
```
Host: 127.0.0.1
Port: 8080
```

<a id="firefox-configuration"></a>
#### Настройка Firefox
```
1. Откройте Firefox Preferences
2. Найдите "proxy"
3. Нажмите "Settings..."
4. Выберите "Manual proxy configuration"
5. HTTP Proxy: 127.0.0.1  Port: 8080
6. Установите "Also use this proxy for HTTPS"
7. Нажмите OK
```

<a id="foxyproxy-extension-recommended"></a>
#### Расширение FoxyProxy (рекомендуется)
```
1. Установите расширение FoxyProxy
2. Добавьте новый прокси:
   - Title: Burp Suite
   - Proxy Type: HTTP
   - Proxy IP: 127.0.0.1
   - Port: 8080
3. Включайте его во время проверки
```

<a id="ssltls-certificate-installation"></a>
### Установка сертификата SSL/TLS

```bash
# Шаг 1: при включённом прокси откройте:
http://burp

# Шаг 2: нажмите "CA Certificate" для скачивания

# Шаг 3: импортируйте сертификат:
# Firefox: Settings → Certificates → Import → Trust for websites
# Chrome: Settings → Security → Manage certificates → Import
# Система: добавьте в доверенные корневые сертификаты
```

<a id="proxy-listeners"></a>
### Слушатели прокси (Proxy Listeners)

```
Proxy → Options → Proxy Listeners

По умолчанию: 127.0.0.1:8080

Добавление собственных слушателей:
- Разные порты для разных проверок
- Привязка ко всем интерфейсам (0.0.0.0) для проверки мобильных приложений
- Перенаправление на другие узлы
```

<a id="invisible-proxy-for-non-proxy-aware-clients"></a>
### Невидимый прокси для клиентов без поддержки прокси

```
1. Proxy → Options → Proxy Listeners
2. Edit listener → Request handling
3. Включите "Support invisible proxying"
4. Настройте файл hosts или DNS
```

<a id="-intercepting-traffic"></a>
## 🎣 Перехват трафика

<a id="intercept-controls"></a>
### Управление перехватом

| Кнопка | Действие |
| -------- | ---------- |
| **Intercept is on/off** | Включить или выключить перехват |
| **Forward** | Отправить запрос серверу |
| **Drop** | Отбросить запрос |
| **Action** | Меню дополнительных действий |

<a id="intercept-options"></a>
### Параметры перехвата

```
Proxy → Options → Intercept Client Requests

Примеры правил:
- Перехватывать только элементы в границах проверки
- Перехватывать только определённые типы файлов
- Исключить изображения и статические файлы
```

<a id="request-modification"></a>
### Изменение запросов

```http
# Исходный запрос
GET /page.php?id=1 HTTP/1.1
Host: target.com

# Изменённый запрос при перехвате
GET /page.php?id=1' OR '1'='1 HTTP/1.1
Host: target.com
```

<a id="match-and-replace"></a>
### Поиск и замена

```
Proxy → Options → Match and Replace

Типичные правила:
- Удалить защитные заголовки
- Изменить User-Agent
- Добавить собственные заголовки
- Заменить параметры запроса
```

| Тип | Найти | Заменить | Назначение |
| ------ | ------- | --------- | --------- |
| Заголовок запроса | `User-Agent: .*` | `User-Agent: Custom` | Изменить User-Agent |
| Тело запроса | `password=test` | `password=admin` | Проверить учётные данные |
| Заголовок ответа | `X-Frame-Options.*` | ` ` | Удалить заголовок |
| Тело ответа | `disabled` | `enabled` | Включить кнопки |

<a id="response-modification"></a>
### Изменение ответов

```
Proxy → Options → Intercept Server Responses

Включить для:
- Удалить защитные заголовки
- Изменить JavaScript
- Изменить содержимое ответа
- Проверить ограничения на стороне клиента
```

<a id="-target--scope"></a>
## 🎯 Цель и границы проверки

<a id="adding-to-scope"></a>
### Добавление в границы проверки

```
Способ 1: правой кнопкой в Site map → Add to scope
Способ 2: Target → Scope → Add (вручную)
Способ 3: из Proxy history → Add to scope
```

<a id="scope-configuration"></a>
### Настройка границ проверки

```
Target → Scope

Включить в границы проверки:
- Protocol: Any/HTTP/HTTPS
- Host/IP: target.com
- Port: Any/Specific
- File: регулярное выражение

Примеры шаблонов:
.*\.target\.com$          # Все поддомены
^https://target\.com/app  # Определённый путь
```

<a id="advanced-scope-settings"></a>
### Расширенная настройка границ

```
Target → Scope → Advanced scope control

Включить:
  Protocol: HTTPS
  Host: target.com
  Port: 443
  File: ^/api/.*

Исключить:
  Host: .*\.google\.com
  File: .*\.(jpg|png|gif|css|js)$
```

<a id="site-map"></a>
### Карта сайта

```
Target → Site map

Возможности:
- Просмотреть всё найденное содержимое
- Фильтровать по границам проверки
- Искать и фильтровать содержимое
- Выделять интересные элементы
- Сравнивать карты сайтов
```

## 🔍 Scanner

<a id="scan-types"></a>
### Виды сканирования

| Тип | Описание | Когда применять |
| ------ | ------------- | ---------- |
| **Passive** | Анализ трафика прокси | Постоянно |
| **Active** | Отправка полезных нагрузок для поиска уязвимостей | С разрешения |
| **Full** | Комплексное сканирование | При наличии времени |
| **Custom** | Только выбранные проверки | Целевая проверка |

<a id="starting-a-scan"></a>
### Запуск сканирования

```
Способ 1: Right-click → Scan
Способ 2: Dashboard → New scan
Способ 3: передача в Scanner из других инструментов
```

<a id="scan-configuration"></a>
### Настройка сканирования

```
Dashboard → New scan → Scan configuration

Встроенные конфигурации:
- Audit checks - all except JavaScript analysis
- Audit checks - critical issues only
- Audit checks - light, active
- Audit checks - medium, active
- Audit checks - full, active
```

<a id="vulnerability-categories"></a>
### Категории уязвимостей

```
Scanner проверяет:

Инъекции:
- SQL-инъекции
- Инъекции команд ОС
- LDAP-инъекции
- XML/XPath-инъекции

Межсайтовый скриптинг:
- Отражённый XSS
- Хранимый XSS
- DOM-based XSS

Аутентификация:
- Ошибки аутентификации
- Ошибки управления сеансами
- Слабые пароли

Прочее:
- CSRF
- Обход каталогов
- Включение файлов
- Раскрытие информации
- Проблемы на стороне сервера
```

<a id="scan-results"></a>
### Результаты сканирования

```
Dashboard → Issue activity
Target → Site map → Issues

Для каждой проблемы:
- Severity (High/Medium/Low/Info)
- Confidence (Certain/Firm/Tentative)
- Описание
- Устранение
- Доказательства (запрос и ответ)
```

<a id="custom-scan-profiles"></a>

<a id="-repeater"></a>
## 🔁 Repeater

<a id="purpose"></a>
### Назначение

Ручное тестирование и изменение отдельных запросов.

<a id="sending-to-repeater"></a>
### Передача запроса в Repeater

```
1. Нажмите правой кнопкой на любой запрос
2. Выберите "Send to Repeater"
3. Клавиши: Ctrl+R
```

<a id="using-repeater"></a>
### Работа с Repeater

```
1. Измените запрос на левой панели
2. Нажмите "Send" (или Ctrl+Space)
3. Просмотрите ответ на правой панели
4. Сравните ответы
```

<a id="repeater-features"></a>
### Возможности Repeater

| Возможность | Описание |
| --------- | ------------- |
| **Несколько вкладок** | Проверка нескольких запросов |
| **История запросов** | Перемещение кнопками < > |
| **Следовать перенаправлениям** | Включение автоматических переходов |
| **Обрабатывать cookie** | Автоматическое обновление cookie |
| **Content-Length** | Автоматическое обновление заголовка |

<a id="testing-examples"></a>
### Примеры проверок

```http
# Проверить SQL-инъекцию
GET /user.php?id=1' HTTP/1.1

# Проверить XSS
GET /search?q=<script>alert(1)</script> HTTP/1.1

# Проверить обход аутентификации
GET /admin HTTP/1.1
Cookie: role=admin

# Проверить IDOR
GET /api/user/1 HTTP/1.1  # Ваш пользователь
GET /api/user/2 HTTP/1.1  # Другой пользователь
```

<a id="-intruder"></a>
## 🔫 Intruder

<a id="attack-types"></a>
### Виды атак

| Тип | Позиции | Полезные нагрузки | Когда применять |
| ------ | ----------- | ---------- | ---------- |
| **Sniper** | 1+ | Один набор, по очереди | Проверка одного параметра |
| **Battering Ram** | 1+ | Один набор, одинаковое значение во всех позициях | Одинаковое значение во всех позициях |
| **Pitchfork** | 1+ | Несколько наборов параллельно | Пары имени пользователя и пароля |
| **Cluster Bomb** | 1+ | Несколько наборов, все комбинации | Полный перебор сочетаний учётных данных |

<a id="sending-to-intruder"></a>
### Передача запроса в Intruder

```
1. Нажмите правой кнопкой на запрос
2. Выберите "Send to Intruder"
3. Клавиши: Ctrl+I
```

<a id="setting-positions"></a>
### Указание позиций

```
Intruder → Positions

Отметьте точки вставки символами §:

GET /login.php?user=§admin§&pass=§test§ HTTP/1.1

Кнопки:
- Add § — отметить выделение
- Clear § — удалить маркеры
- Auto § — определить автоматически
```

<a id="payload-types"></a>
### Типы полезной нагрузки

| Тип | Описание |
| ------ | ------------- |
| **Simple list** | Пользовательский словарь |
| **Runtime file** | Загрузка из файла |
| **Numbers** | Последовательные или случайные числа |
| **Dates** | Последовательности дат |
| **Brute forcer** | Комбинации символов |
| **Null payloads** | Пустые полезные нагрузки (проверка частоты запросов) |
| **Username generator** | Типовые шаблоны имён пользователей |

<a id="payload-processing"></a>
### Обработка полезной нагрузки

```
Intruder → Payloads → Payload Processing

Добавить правила:
- Добавить префикс или суффикс
- URL-кодирование
- Кодирование Base64
- Хеширование (MD5, SHA)
- Поиск и замена
```

<a id="grep---match"></a>
### Grep - Match

```
Intruder → Options → Grep - Match

Добавьте строки для выделения в ответах:
- "Login successful"
- "Invalid password"
- "error"
- Собственное регулярное выражение

Помогает выявлять успешные попытки.
```

<a id="attack-examples"></a>
### Примеры атак

#### Перебор учётных данных

```
Тип атаки: Cluster bomb
Полезная нагрузка 1: список имён пользователей
Полезная нагрузка 2: список паролей
```

<a id="fuzzing-parameters"></a>
#### Фаззинг параметров
```
GET /api/user/§1§ HTTP/1.1

Тип атаки: Sniper
Полезная нагрузка: числа 1-1000
```

<a id="content-discovery"></a>
#### Поиск содержимого
```
GET /§admin§ HTTP/1.1

Тип атаки: Sniper
Полезная нагрузка: словарь каталогов
Фильтр: код состояния != 404
```

<a id="encodingdecoding"></a>
### Кодирование и декодирование

```
Вкладка Decoder

Операции:
- URL-кодирование и декодирование
- HTML-кодирование и декодирование
- Кодирование и декодирование Base64
- Шестнадцатеричное кодирование и декодирование
- Сжатие и распаковка Gzip
- ASCII Hex
- Binary
```

<a id="smart-decode"></a>
### Автоматическое декодирование (Smart Decode)

```
Decoder → Smart decode

Автоматически распознаёт и декодирует:
- Base64
- URL-кодирование
- HTML-сущности
- Сочетания разных кодировок
```

<a id="common-uses"></a>
### Типичные применения

> **Уточнение JWT:** показана сокращённая строка-пример. В подписанном JWT заголовок и payload кодируются Base64url и разделены точками; декодирование не проверяет подпись. См. [руководство PortSwigger по JWT](https://portswigger.net/web-security/jwt). Исходные строки сохранены.

```
# Декодировать JWT
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
→ Decode as Base64

# Декодировать параметр URL
%3Cscript%3Ealert(1)%3C%2Fscript%3E
→ URL decode
→ <script>alert(1)</script>

# Закодировать полезную нагрузку
<script>alert(1)</script>
→ Base64 encode
→ Использовать в проверке
```

<a id="-sequencer"></a>
## 🔢 Sequencer

<a id="purpose-2"></a>
### Назначение

Анализ качества случайности токенов: идентификаторов сеансов и CSRF-токенов.

<a id="how-to-use-1"></a>
### Порядок работы

```
1. Перехватите запрос, ответ на который содержит токен
2. Правой кнопкой → Send to Sequencer
3. Укажите расположение токена
4. Запустите захват (live capture)
5. Проанализируйте результаты
```

<a id="analysis-metrics"></a>
### Показатели анализа

| Показатель | Хорошее значение | Описание |
| -------- | ------------ | ------------- |
| **Overall quality** | >100 bits | Оценка случайности |
| **Character-level** | Высокая энтропия | Случайность отдельных символов |
| **Bit-level** | Высокая энтропия | Случайность отдельных битов |

<a id="interpretation"></a>
### Интерпретация результатов

> **Уточнение:** результаты [Sequencer](https://portswigger.net/burp/documentation/desktop/tools) оценивают случайность выборки. Оценку Excellent не следует считать формальным доказательством криптографической стойкости генератора.

```
Результаты:
- Excellent: токен выглядит криптографически случайным
- Good: приемлем для большинства применений
- Poor: потенциально предсказуем
- Very poor: токен может поддаваться угадыванию
```

<a id="-testing-workflow"></a>
## 🎯 Последовательность тестирования

<a id="standard-web-app-test-flow"></a>
### Типовой порядок проверки веб-приложения

```
Шаг 1: настройка
├── Настроить прокси браузера
├── Установить сертификат SSL
└── Определить границы проверки

Шаг 2: разведка
├── Вручную просмотреть приложение
├── Запустить Spider/Crawler
└── Изучить Site map

Шаг 3: анализ
├── Проверить Proxy history
├── Изучить результаты пассивного анализа
└── Определить поверхность атаки

Шаг 4: тестирование
├── Проверить вручную с Repeater
├── Выполнить автоматизированные проверки с Intruder
├── Запустить активное сканирование
└── Использовать расширения

Шаг 5: отчёт
├── Проверить все выявленные проблемы
├── Создать отчёт
└── Зафиксировать доказательства
```

<a id="testing-checklist"></a>
### Список проверок

```
Аутентификация:
□ Перебор учётных данных
□ Политика паролей
□ Блокировка учётной записи
□ Управление сеансами
□ Функция запоминания входа

Авторизация:
□ Проверка IDOR
□ Повышение привилегий
□ Доступ к отдельным функциям

Проверка входных данных:
□ SQL-инъекция
□ XSS (отражённый, хранимый, DOM)
□ Инъекция команд
□ Загрузка файлов
□ XXE

Сеансы:
□ Фиксация сеанса
□ Время ожидания сеанса
□ Случайность токенов

Бизнес-логика:
□ Изменение цены
□ Обход бизнес-процесса
□ Состояния гонки
```

<a id="-tips--best-practices"></a>
## 💡 Советы и рекомендуемые практики

<a id="performance-tips"></a>
### Производительность

1. **Ограничивать границы проверки**
   ```
   Оставлять в границах проверки только целевые домены
   Это уменьшает лишние записи в Proxy history
   ```

2. **Отключать расширения**
   ```
   Отключать неиспользуемые расширения для повышения производительности
   ```

3. **Использовать файлы проектов**
   ```
   Регулярно сохранять работу
   Использовать файлы проектов для больших проверок
   ```

<a id="testing-tips"></a>
### Советы по тестированию

1. **Начинать с пассивного анализа**
   ```
   Сначала использовать пассивный анализ для поиска очевидных проблем
   Проверять результаты до активного сканирования
   ```

2. **Сначала использовать Repeater**
   ```
   Ручное тестирование помогает выявлять дополнительные особенности
   Разобраться в приложении до автоматизации
   ```

3. **Упорядочивать вкладки**
   ```
   Давать вкладкам Repeater понятные имена
   Называть атаки Intruder
   ```

<a id="avoiding-detection"></a>
### Снижение заметности

```
Настройки снижения заметности:

Project options → Connections:
- Ограничить частоту запросов
- Случайные задержки
- Ограничить число одновременных соединений

Intruder → Options:
- Задержка между запросами
- Время начала
```

<a id="troubleshooting"></a>
### Устранение неполадок

| Проблема | Решение |
| ------- | ---------- |
| Не получается перехватить HTTPS | Установить сертификат CA |
| Низкая производительность | Сократить границы проверки и отключить расширения |
| Запросы отсутствуют | Проверить "Intercept Server Responses" |
| Scanner не находит уязвимости | Увеличить интенсивность проверок |
