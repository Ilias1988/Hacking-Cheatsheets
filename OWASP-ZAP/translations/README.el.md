## Πριν ξεκινήσετε

Το **ZAP** (Zed Attack Proxy) είναι εργαλείο επιθεώρησης και ελέγχου εφαρμογών web. Ο **proxy** καταγράφει την κίνηση browser–server. Το **Spider** ακολουθεί συνδέσμους για να ανακαλύψει σελίδες και το **AJAX Spider** χρησιμοποιεί browser για εφαρμογές με JavaScript. Η **παθητική ανάλυση** εξετάζει την καταγεγραμμένη κίνηση, ενώ ο **ενεργός έλεγχος** στέλνει πρόσθετα δοκιμαστικά αιτήματα.

Ένα **Context** ομαδοποιεί σχετικά URL με κοινές ρυθμίσεις, όπως ταυτοποίηση και διαχείριση συνεδρίας. Το **scope** ορίζει ποια από αυτά βρίσκονται εντός του συμφωνημένου ελέγχου. Το **alert** είναι ειδοποίηση για πιθανό πρόβλημα, όχι πάντοτε επιβεβαιωμένη ευπάθεια. Το **API** επιτρέπει σε άλλα προγράμματα να ελέγχουν το ZAP και το **Automation Framework** οργανώνει μια ακολουθία εργασιών.

Ο **Fuzzer** αντικαθιστά επιλεγμένα σημεία ενός αιτήματος με πολλές δοκιμαστικές τιμές (**payloads**), ώστε να συγκρίνετε τις αποκρίσεις.

Διατηρούνται τα αγγλικά ονόματα επιλογών και μενού, με ελληνικές οδηγίες χρήσης. Οι εντολές, τα παραδείγματα Python και οι ρυθμίσεις YAML παραμένουν όπως στο πρωτότυπο. Διαβάστε τις σημειώσεις συμβατότητας πριν τα χρησιμοποιήσετε στο εργαστήριό σας.

## 🎯 Εισαγωγή

**Το ZAP** (Zed Attack Proxy, γνωστό και ως OWASP ZAP) είναι δωρεάν εργαλείο ανοιχτού κώδικα για ελέγχους ασφάλειας εφαρμογών web. Συνδυάζει proxy επιθεώρησης, εργαλεία χειροκίνητων ελέγχων και αυτοματοποιημένη σάρωση.

### Δυνατότητες του ZAP

| Χαρακτηριστικό | Περιγραφή |
| --------- | ------------- |
| **Δωρεάν και ανοιχτού κώδικα** | Χωρίς κόστος άδειας, με ανάπτυξη από την κοινότητα |
| **Προσιτό στη χρήση** | Κατάλληλο για τα πρώτα βήματα, με δυνατότητες προχωρημένων ελέγχων |
| **Αυτοματοποιημένη σάρωση** | Εξερεύνηση, ενεργοί έλεγχοι και παθητική ανάλυση |
| **Χειροκίνητοι έλεγχοι** | Proxy επιθεώρησης και εργαλείο fuzzing |
| **Υποστήριξη API** | REST API για αυτοματοποίηση |
| **Πολλαπλές πλατφόρμες** | Windows, Linux, macOS και Docker |
| **Επεκτάσιμο** | Marketplace με πολλά πρόσθετα |

### Σύγκριση ZAP και Burp Suite

> **Πώς διαβάζεται η σύγκριση:** Η τιμή και οι γενικές ενδείξεις «Pro only» του πρωτοτύπου δεν καλύπτουν όλες τις σημερινές δυνατότητες. Ο ενσωματωμένος Scanner του Burp διαφέρει από τα APIs προσθέτων και τους μηχανισμούς αυτοματοποίησης. Για ακριβή σύγκριση, ελέγξτε τη συγκεκριμένη λειτουργία και έκδοση.


| Χαρακτηριστικό | ZAP | Burp Suite |
| --------- | ----- | ------------ |
| **Κόστος** | Δωρεάν | Συνδρομή· ελέγξτε την επίσημη τρέχουσα τιμή |
| **Ανοιχτού κώδικα** | ✅ Ναι | ❌ Όχι |
| **Αυτοματοποιημένη σάρωση** | ✅ Full — εκτενής έλεγχος | Εξαρτάται από την έκδοση και τη συγκεκριμένη δυνατότητα |
| **Πρόσβαση μέσω API** | ✅ Δωρεάν | Εξαρτάται από την έκδοση και τη συγκεκριμένη δυνατότητα |
| **Ενεργή ανάπτυξη** | ✅ Ναι | ✅ Ναι |
| **Community** | OWASP | PortSwigger |

## 📥 Εγκατάσταση

> **Συμβατότητα:** Ορισμένα ονόματα πακέτων, μενού και επιλογών του πρωτοτύπου εξαρτώνται από έκδοση, λειτουργικό και εγκατεστημένα πρόσθετα. Χρησιμοποιήστε την [επίσημη τεκμηρίωση ZAP](https://www.zaproxy.org/docs/) για αντιστοίχιση. Η ονομασία OWASP ZAP διατηρείται ως ιστορική αναφορά, χωρίς ισχυρισμό για τη σημερινή οργανωτική υπαγωγή του έργου.


### Windows
```bash
# Λήψη από τον επίσημο ιστότοπο
https://www.zaproxy.org/download/

# Εναλλακτικά μέσω Chocolatey
choco install owasp-zap
```

### Linux (Kali και Ubuntu)
```bash
# Kali, εφόσον είναι προεγκατεστημένο
zaproxy

# Ubuntu/Debian
sudo apt install zaproxy

# Εγκατάσταση μέσω Snap
sudo snap install zaproxy --classic
```

### macOS
```bash
# Homebrew
brew install --cask owasp-zap

# Λήψη αρχείου DMG από τον επίσημο ιστότοπο
```

### Docker

> **Τοπική πρόσβαση:** Το `-host 0.0.0.0` και η δημοσίευση θυρών Docker μπορούν να καταστήσουν το ZAP προσβάσιμο από άλλα συστήματα. Ορίστε την απαιτούμενη πρόσβαση και προστατέψτε το κλειδί API. Τα παραδείγματα Webswing και γραμμής εντολών απαιτούν τις αντίστοιχες δυνατότητες της εικόνας.

```bash
# Λήψη της εικόνας του παραδείγματος
docker pull ghcr.io/zaproxy/zaproxy:stable

# Εκκίνηση ZAP στο παρασκήνιο χωρίς γραφικό περιβάλλον
docker run -u zap -p 8080:8080 -i ghcr.io/zaproxy/zaproxy:stable zap.sh -daemon -host 0.0.0.0 -port 8080

# Εκκίνηση γραφικού περιβάλλοντος μέσω Webswing σε Linux
docker run -u zap -p 8080:8080 -p 8090:8090 -v /tmp:/zap/wrk/:rw \
    --rm -it ghcr.io/zaproxy/zaproxy:stable zap-webswing.sh
```

### Επιβεβαίωση εγκατάστασης
```bash
# Εκκίνηση ZAP
zaproxy
zap.sh       # Linux
zap.bat      # Windows
```

| 📊 | Reports — αναφορές |

### Τρόποι λειτουργίας

> **Σημασία των modes:** Το Safe απαγορεύει ορισμένες δυνητικά επικίνδυνες λειτουργίες· το Protected τις περιορίζει σε URL εντός scope. Το ATTACK ξεκινά ενεργούς ελέγχους σε νέους κόμβους εντός scope μόλις ανακαλύπτονται. Κανένα mode δεν αντικαθιστά την εξουσιοδότηση ή τον σωστό ορισμό στόχων. Δείτε τα [modes του ZAP](https://www.zaproxy.org/docs/desktop/start/features/modes/).


| Λειτουργία | Περιγραφή |
| ------ | ------------- |
| **Safe — περιορισμένες ενέργειες** | Απενεργοποιεί ορισμένες δυνητικά επικίνδυνες ενέργειες |
| **Protected — προστατευμένος τρόπος λειτουργίας** | Περιορίζει ορισμένες ενέργειες στους στόχους εντός scope |
| **Standard — κανονική λειτουργία** | Κανονική λειτουργία χωρίς τους περιορισμούς Safe/Protected |
| **ATTACK** | Αυτόματη ενεργός σάρωση νέων κόμβων εντός scope |

## 🔌 Ρύθμιση proxy

> **Πιστοποιητικά και μενού:** Εισαγωγή του CA επιτρέπει επιθεώρηση HTTPS από τον proxy. Χρησιμοποιήστε εργαστηριακό προφίλ browser. Η διαδρομή Local Proxies και η λήψη CA μέσω `http://zap` δεν είναι ίδιες σε κάθε έκδοση· ελέγξτε τις ρυθμίσεις Network/Server Certificates της εγκατάστασής σας.


### Ρύθμιση προγράμματος περιήγησης

**Προεπιλεγμένος proxy ZAP:**
```
Host: localhost (127.0.0.1) (τοπικός proxy)
Port: 8080 (θύρα proxy)
```

### Ρύθμιση Firefox
```
1. Settings → Network Settings → Manual proxy (χειροκίνητος proxy στις ρυθμίσεις δικτύου)
2. HTTP Proxy: 127.0.0.1  Port: 8080 (διεύθυνση και θύρα τοπικού proxy)
3. Ενεργοποιήστε το "Also use this proxy for HTTPS", όπου εμφανίζεται
4. Εναλλακτικά χρησιμοποιήστε το πρόσθετο FoxyProxy
```

### Εισαγωγή πιστοποιητικού ZAP
```
1. Στον browser επισκεφθείτε: http://zap
2. Πατήστε "Download ZAP Root CA Certificate" για λήψη πιστοποιητικού, όπου διατίθεται
3. Εισαγωγή στον browser:
   Firefox: Settings → Privacy → Certificates → Import (εισαγωγή πιστοποιητικού)
   Chrome: Settings → Security → Manage certificates (διαχείριση πιστοποιητικών)
```

### Ρύθμιση τοπικού proxy ZAP
```
Μενού: Tools → Options → Local Proxies

Ρυθμίσεις:
- Address: localhost (τοπική διεύθυνση ακρόασης)
- Port: 8080 (θύρα proxy)
- Behind NAT: Enable if needed (ρύθμιση NAT, όπου διατίθεται και απαιτείται)
- Remove unsupported encodings: Enable (αφαίρεση μη υποστηριζόμενων κωδικοποιήσεων)
```

### Επόμενος proxy στη διαδρομή σύνδεσης (Proxy Chain)
```
Μενού: Tools → Options → Network → Connection

Χρήση αλυσίδας proxy:
- Address: corporate-proxy.com (διεύθυνση επόμενου proxy)
- Port: 8080 (θύρα proxy)
- Ταυτοποίηση, αν απαιτείται
```

## 🔧 Χειροκίνητοι έλεγχοι

### Παύση και επιθεώρηση αιτημάτων (Break)

```
1. Πατήστε το κουμπί "Break" (🛑) στη γραμμή εργαλείων
2. Περιηγηθείτε στην εφαρμογή
3. Τροποποιήστε το αίτημα που έχει σταματήσει για επιθεώρηση
4. Πατήστε "Submit and Continue" για προώθηση ή "Drop" για απόρριψη

Επιλογές παύσης για επιθεώρηση:
- Παύση σε όλα τα αιτήματα
- Παύση σε όλες τις αποκρίσεις
- Παύση σε συγκεκριμένο μοτίβο URL
```

### Επεξεργαστής αιτημάτων (Request Editor)

```
Δεξί κλικ στο αίτημα → Open/Resend with Request Editor

Δυνατότητες:
- Τροποποιήστε το επιθυμητό τμήμα του αιτήματος
- Προσθήκη και αφαίρεση κεφαλίδων HTTP
- Αλλαγή μεθόδου HTTP
- Στείλτε το αίτημα και εξετάστε την απόκριση
```

### Χειροκίνητο αίτημα
```
Μενού: Tools → Manual Request Editor

Εναλλακτικά: Ctrl+M

Δημιουργήστε προσαρμοσμένα αιτήματα από την αρχή
```

### Κωδικοποίηση, αποκωδικοποίηση και υπολογισμός hash
```
Μενού: Tools → Encode/Decode/Hash

Υποστηρίζει:
- Κωδικοποίηση και αποκωδικοποίηση URL
- Κωδικοποίηση και αποκωδικοποίηση Base64
- Κωδικοποίηση και αποκωδικοποίηση HTML
- Κωδικοποίηση και αποκωδικοποίηση δεκαεξαδικής μορφής
- Υπολογισμός hash με MD5, SHA1 ή SHA256
```

### Λειτουργία αναζήτησης
```
Καρτέλα Search → εισαγωγή μοτίβου αναζήτησης

Αναζήτηση σε:
- Διευθύνσεις URL
- Αιτήματα
- Αποκρίσεις
- Κεφαλίδες HTTP
- Πολλές πλατφόρμες, όπου υποστηρίζονται
```

## 🕷️ Αυτόματη εξερεύνηση ιστοτόπου

> **Η εξερεύνηση στέλνει αιτήματα:** Spider και AJAX Spider ακολουθούν συνδέσμους και ενδέχεται να αλληλεπιδρούν με φόρμες. Η επιλογή Post forms μπορεί να αλλάξει δεδομένα ή συνεδρίες. Οι τιμές βάθους, χρόνου και threads είναι παραδείγματα του πρωτοτύπου, όχι επιβεβαιωμένες τρέχουσες προεπιλογές.


### Κλασική εξερεύνηση με Spider

```
Δεξί κλικ στον στόχο → Spider → Spider...

Εναλλακτικά: Ctrl+Alt+S

Επιλογές:
- Μέγιστο βάθος εξερεύνησης
- Μέγιστος αριθμός παιδιών ανά κόμβο
- Μέγιστη διάρκεια
- Διαχείριση παραμέτρων
```

### Επιλογές Spider
```
Μενού: Tools → Options → Spider

Ρυθμίσεις:
- Max Depth: 5-10 (default: 5) — βάθος και προεπιλογή που αναφέρει το πρωτότυπο
- Max Children: 10 (μέγιστος αριθμός παιδιών ανά κόμβο στο παράδειγμα)
- Max Duration: 0 (unlimited) — χωρίς χρονικό όριο στο παράδειγμα
- Thread Count: 5 (πέντε παράλληλες εργασίες στο παράδειγμα)
- Handle forms: Yes (επεξεργασία φορμών)
- Post forms: Yes (υποβολή φορμών, που μπορεί να αλλάξει δεδομένα)
```

### AJAX Spider

```
Για εφαρμογές με εκτεταμένη χρήση JavaScript:

Δεξί κλικ στον στόχο → AJAX Spider → AJAX Spider...

Απαιτεί κατάλληλο browser:
- Firefox (προτεινόμενο στο πρωτότυπο)
- Chrome
- HtmlUnit (χωρίς γραφικό περιβάλλον, όπου υποστηρίζεται)
```

### Επιλογές AJAX Spider
```
Μενού: Tools → Options → AJAX Spider

Ρυθμίσεις:
- Browser: Firefox (browser για την εξερεύνηση)
- Max Crawl Depth: 10 (μέγιστο βάθος εξερεύνησης στο παράδειγμα)
- Max Crawl States: 0 (unlimited) — χωρίς όριο καταστάσεων στο παράδειγμα
- Max Duration: 60 minutes (μέχρι 60 λεπτά στο παράδειγμα)
- Αλληλεπίδραση με τα προεπιλεγμένα στοιχεία της σελίδας
- Αλληλεπίδραση με στοιχεία που έχουν onclick ή αντίστοιχους χειριστές
```

## ⚡ Ενεργός έλεγχος (Active Scanning)

### Εκκίνηση ενεργού ελέγχου

```
Δεξί κλικ στον στόχο → Active Scan...

Εναλλακτικά: Ctrl+Alt+A

Ρυθμίστε:
- Starting Point (αφετηρία ελέγχου)
- Context (προαιρετικό πλαίσιο ελέγχου)
- User (χρήστης για ταυτοποίηση)
- Policy (πολιτική σάρωσης)
- Technology — τεχνολογία
```

### Πολιτικές σάρωσης

```
Μενού: Analyze → Scan Policy Manager

Δημιουργήστε ή τροποποιήστε πολιτικές ελέγχου:
- Ποιοι έλεγχοι θα εκτελεστούν
- Threshold (κατώφλι ευαισθησίας για αναφορά ευρήματος)
- Strength (ένταση και αριθμός δοκιμών)
```

### Κατηγορίες πολιτικής ελέγχου

| Κατηγορία | Έλεγχοι |
| ---------- | ------- |
| **Έγχυση μη έμπιστων δεδομένων (Injection)** | Έγχυση SQL, εντολών λειτουργικού και LDAP |
| **Πρόγραμμα περιήγησης χρήστη** | XSS και DOM XSS |
| **Ασφάλεια διακομιστή** | Συμπερίληψη απομακρυσμένων αρχείων |
| **Πληροφορίες** | Διάσχιση καταλόγων και αποκάλυψη πληροφοριών |
| **Διάφορα** | Ανακατευθύνσεις που επηρεάζονται από είσοδο χρήστη |

### Ένταση σάρωσης

| Επίπεδο | Περιγραφή |
| ------- | ------------- |
| **Low — χαμηλή ένταση** | Λιγότερα αιτήματα, συνήθως ταχύτερα |
| **Medium — μέση ένταση** | Ισορροπημένο |
| **High — υψηλή ένταση** | Περισσότερα αιτήματα και εκτενέστεροι έλεγχοι |
| **Insane — μέγιστη ένταση** | Μέγιστος αριθμός ελέγχων, πιο αργά |

### Επιλογή τεχνολογιών
```
Δεξί κλικ στον στόχο → Technology → Select...

Περιορίστε τις σαρώσεις ανά τεχνολογία:
- Τεχνολογίες PHP, ASP και JSP
- Βάσεις δεδομένων MySQL, PostgreSQL και Oracle
- Διακομιστές Apache, IIS και Nginx
- Λειτουργικά συστήματα Linux και Windows
```

## 👁️ Παθητική ανάλυση (Passive Scanning)

> **Όρια παθητικής ανάλυσης:** Η παθητική ανάλυση δεν στέλνει δικά της πρόσθετα δοκιμαστικά αιτήματα. Η περιήγηση ή η εξερεύνηση που παράγει την κίνηση εξακολουθεί να στέλνει αιτήματα. Η αναφορά Weak SSL/TLS του πρωτοτύπου δεν σημαίνει πλήρη έλεγχο πρωτοκόλλων και κρυπτογραφικών ρυθμίσεων TLS.


### Τι είναι η παθητική ανάλυση;

Αναλύει την κίνηση που έχει ήδη καταγραφεί, χωρίς να στέλνει πρόσθετα δοκιμαστικά αιτήματα.

```
Αυτόματη ανάλυση καταγεγραμμένης κίνησης, εφόσον η λειτουργία είναι ενεργή

Αναζητά ενδείξεις για:
- Κεφαλίδες ασφάλειας που λείπουν
- Αποκάλυψη πληροφοριών
- Προβλήματα cookies
- Ενδείξεις αδυναμιών SSL/TLS, όπου υποστηρίζονται· όχι πλήρης έλεγχος TLS
- Αποκάλυψη ιδιωτικής IP
```

### Passive Scan Rules — κανόνες παθητικής ανάλυσης

```
Μενού: Analyze → Scan Policy Manager → Passive Scan

Ενδεικτικοί κανόνες:
- Application Error Disclosure (αποκάλυψη σφάλματος εφαρμογής)
- Cookie Without Secure Flag (cookie χωρίς σημαία Secure)
- Cross-Domain JavaScript (JavaScript από άλλο domain)
- Αποκάλυψη πληροφοριών
- Private IP Disclosure (αποκάλυψη ιδιωτικής IP)
- X-Frame-Options Header Missing (λείπει η κεφαλίδα X-Frame-Options)
```

### Ρύθμιση παθητικής ανάλυσης
```
Μενού: Tools → Options → Passive Scan

Ρυθμίσεις:
- Scan only in scope: Recommended (περιορισμός στα εγκεκριμένα όρια ελέγχου)
- Max alerts per rule: 10 (όριο ειδοποιήσεων ανά κανόνα)
- Tags: Enable (ενεργοποίηση ετικετών)
```

## 🎯 Πλαίσια ελέγχου και συνεδρίες (Contexts & Sessions)

> **Ταυτοποίηση και scope:** Η δημιουργία Context δεν αποδεικνύει ότι ο σαρωτής παραμένει συνδεδεμένος ως ο σωστός χρήστης. Επαληθεύστε τις ενδείξεις σύνδεσης/αποσύνδεσης και τα αιτήματα του επιλεγμένου χρήστη. Context, χρήστης και scope πρέπει να συμφωνούν με τον επιδιωκόμενο έλεγχο.


### Τι είναι τα Contexts;

Είναι λογικές ομάδες σχετικών URL για οργανωμένους ελέγχους με κοινές ρυθμίσεις.

### Δημιουργία Context
```
Δεξί κλικ στο Sites → Include in Context → New Context

Εναλλακτικό μενού: File → New Context
```

### Ρυθμίσεις Context

| Ρύθμιση | Σκοπός |
| --------- | --------- |
| **Include in Context — συμπερίληψη στο πλαίσιο ελέγχου** | URL που συμπεριλαμβάνονται |
| **Exclude from Context — εξαίρεση από το πλαίσιο ελέγχου** | URL που εξαιρούνται |
| **Technology — τεχνολογία** | Τεχνολογία διακομιστή |
| **Ταυτοποίηση** | Μέθοδος σύνδεσης |
| **Διαχείριση συνεδριών** | Διαχείριση cookies και tokens |
| **Users — χρήστες** | Λογαριασμοί χρηστών για έλεγχο |

### Τύποι ταυτοποίησης

| Τύπος | Χρήση |
| ------ | ---------- |
| **Form-based — μέσω φόρμας** | Φόρμες σύνδεσης |
| **HTTP Basic** | Βασική ταυτοποίηση HTTP |
| **JSON-based — μέσω JSON** | Ταυτοποίηση σε API |
| **Script-based — μέσω script** | Προσαρμοσμένη ταυτοποίηση |

### Ταυτοποίηση μέσω φόρμας
```
1. Καταγράψτε το αίτημα σύνδεσης στο ZAP
2. Δεξί κλικ → Include in Context
3. Μενού: Context → Authentication → Form-based
4. Ορίστε το URL σύνδεσης (Login URL)
5. Ορίστε τα δεδομένα POST του αιτήματος σύνδεσης (Login Request POST Data)
6. Καθορίστε τις παραμέτρους ονόματος χρήστη και κωδικού
7. Ορίστε ενδείξεις που αναγνωρίζουν αν ο χρήστης είναι συνδεδεμένος ή αποσυνδεδεμένος
```

### Διαχείριση συνεδριών
```
Μενού: Context → Session Management

Τύποι:
- Cookie-based (διαχείριση μέσω cookies, συνήθης περίπτωση)
- HTTP Auth (ταυτοποίηση HTTP)
- Script-based — μέσω script
```

### Users — χρήστες
```
Μενού: Context → Users → Add

Προσθέστε χρήστες για τον έλεγχο:
- Name: admin (όνομα χρήστη στο παράδειγμα)
- Credentials: admin/password123 (ενδεικτικό όνομα χρήστη και κωδικός)
```

## 🎲 Fuzzer

### Εκκίνηση Fuzzer
```
1. Επιλέξτε αίτημα στο History
2. Δεξί κλικ → Attack → Fuzz...
3. Επιλέξτε το σημείο που θα δέχεται τις δοκιμαστικές τιμές

```

### Ορισμός σημείου δοκιμής
```
1. Στο παράθυρο Fuzzer, επιλέξτε το κείμενο που θα αντικαθίσταται
2. Πατήστε "Add..."
3. Επιλέξτε τύπο δοκιμαστικών δεδομένων
```

### Τύποι δοκιμαστικών δεδομένων (payloads)

| Τύπος | Περιγραφή |
| ------ | ------------- |
| **Strings — συμβολοσειρές** | Προσαρμοσμένη λίστα συμβολοσειρών |
| **Αρχείο** | Φόρτωση από αρχείο |
| **File Fuzzers — λίστες δοκιμαστικών τιμών** | Έτοιμες λίστες λέξεων |
| **Numbers — αριθμοί** | Ακολουθίες αριθμών |
| **Regex — κανονική έκφραση** | Παραγωγή τιμών βάσει κανονικής έκφρασης |
| **Script — πρόγραμμα εντολών** | Προσαρμοσμένο script |

### Έτοιμες συλλογές δεδομένων fuzzing
```
Μενού: Add → File Fuzzers

Κατηγορίες:
- jbrofuzz (δοκιμαστικά δεδομένα XSS, SQL και άλλων κατηγοριών)
```

### Επιλογές Fuzzer
```
Επιλογές:
- Παράλληλες εργασίες

- Ακολούθηση ανακατευθύνσεων
- Εμφάνιση όλων των αποτελεσμάτων ή εφαρμογή φίλτρων
```

### Παράδειγμα Fuzzer: δοκιμές τιμών παραμέτρου
```
1. Καταγράψτε το αίτημα: GET /page?id=1
2. Δεξί κλικ → Fuzz
3. Επιλέξτε το κείμενο "1"
```

## 🤖 API και αυτοματοποίηση

### Ενεργοποίηση API
```
Μενού: Tools → Options → API

Ρυθμίσεις:
- Enabled: Yes (ενεργό)
- API Key: (auto-generated or custom) — αυτόματα δημιουργημένο ή δικό σας κλειδί API
- Permitted addresses: localhost (επιτρεπόμενη πρόσβαση από το τοπικό σύστημα)
```

### Πρόσβαση μέσω API
```bash
# Βασική διεύθυνση API
http://localhost:8080/JSON/

# Με κλειδί API
http://localhost:8080/JSON/core/view/alerts/?apikey=YOUR_API_KEY

# Ανάκτηση έκδοσης
curl "http://localhost:8080/JSON/core/view/version/?apikey=API_KEY"
```

### Συνήθη σημεία πρόσβασης API (endpoints)

| Σημείο πρόσβασης | Σκοπός |
| ---------- | --------- |
| `/core/view/alerts/` | Ανάκτηση ειδοποιήσεων |
| `/core/view/hosts/` | Ανάκτηση συστημάτων που έχουν καταγραφεί |
| `/spider/action/scan/` | Εκκίνηση Spider |
| `/ascan/action/scan/` | Εκκίνηση ενεργού ελέγχου |
| `/core/view/urls/` | Ανάκτηση καταγεγραμμένων URL |
| `/core/action/shutdown/` | Τερματισμός ZAP |

### Παραδείγματα API

```bash
# Εκκίνηση εξερεύνησης URL με Spider
curl "http://localhost:8080/JSON/spider/action/scan/?url=http://target.com&apikey=API_KEY"

# Έλεγχος προόδου Spider
curl "http://localhost:8080/JSON/spider/view/status/?apikey=API_KEY"

# Εκκίνηση ενεργού ελέγχου
curl "http://localhost:8080/JSON/ascan/action/scan/?url=http://target.com&apikey=API_KEY"

# Ανάκτηση ειδοποιήσεων
curl "http://localhost:8080/JSON/core/view/alerts/?apikey=API_KEY"

# Δημιουργία αναφοράς HTML
curl "http://localhost:8080/OTHER/core/other/htmlreport/?apikey=API_KEY" > report.html
```

### Χρήση API μέσω Python

> **Το παράδειγμα δεν περιμένει ολοκλήρωση:** Οι κλήσεις εκκίνησης Spider και Active Scan επιστρέφουν πριν τελειώσει ο έλεγχος. Η άμεση ανάκτηση alerts μπορεί να δώσει ελλιπή εικόνα. Παρακολουθήστε τα αναγνωριστικά σάρωσης, την πρόοδο και την ουρά παθητικής ανάλυσης πριν από την τελική αναφορά. Δείτε το [API του ZAP](https://www.zaproxy.org/docs/api/).

```python
from zapv2 import ZAPv2

# Σύνδεση στο ZAP
zap = ZAPv2(apikey='your-api-key', proxies={'http': 'http://127.0.0.1:8080'})

# Spider
zap.spider.scan(url='http://target.com')

# Ενεργός έλεγχος
zap.ascan.scan(url='http://target.com')

# Ανάκτηση ειδοποιήσεων
alerts = zap.core.alerts()
for alert in alerts:
    print(f"{alert['risk']}: {alert['name']}")
```

```bash
# Εκτέλεση πλάνου αυτοματοποίησης
zap.sh -cmd -autorun automation.yaml
```

### Παράδειγμα αυτοματοποίησης σε YAML

> **Ενδεικτικό πλάνο:** Το YAML περιλαμβάνει ενεργό έλεγχο. Ελέγξτε τα υποστηριζόμενα πεδία κάθε job στην έκδοσή σας· η παράμετρος `scanOnlyInScope` του πρωτοτύπου δεν πρέπει να θεωρηθεί μόνη της επιβεβαιωμένος περιορισμός πεδίου. Ορίστε ρητά το κατάλληλο Context και επαληθεύστε το πλάνο. Δείτε την [τεκμηρίωση activeScan job](https://www.zaproxy.org/docs/desktop/addons/automation-framework/job-ascan/).

```yaml
env:
  contexts:
    - name: "Default Context"
      urls:
        - "http://target.com"

jobs:
  - type: spider
    parameters:
      url: "http://target.com"
      maxDuration: 5
      
  - type: passiveScan-wait
    parameters:
      maxDuration: 5
      
  - type: activeScan
    parameters:
      scanOnlyInScope: true
      
  - type: report
    parameters:
      template: "traditional-html"
      reportFile: "report.html"
```

### Σαρώσεις μέσω Docker

> **Baseline και αναφορές:** Το Baseline εκτελεί Spider και έπειτα παθητική ανάλυση, χωρίς Active Scan· συνεπώς παράγει δικτυακή κίνηση. Για μόνιμη αποθήκευση αναφορών Docker χρειάζεται κατάλληλη αντιστοίχιση καταλόγου και δικαιώματα εγγραφής· το `-r report.html` μόνο του δεν αποθηκεύει αυτόματα το αρχείο στον υπολογιστή σας. Δείτε τις [οδηγίες Baseline Scan](https://www.zaproxy.org/docs/docker/baseline-scan/).


```bash
# Baseline: εξερεύνηση με Spider και παθητική ανάλυση, χωρίς ενεργό έλεγχο
docker run -t ghcr.io/zaproxy/zaproxy:stable zap-baseline.py \
    -t https://target.com \
    -r report.html

# Πλήρης σάρωση με ενεργούς ελέγχους
docker run -t ghcr.io/zaproxy/zaproxy:stable zap-full-scan.py \
    -t https://target.com \
    -r report.html

# Έλεγχος API
docker run -t ghcr.io/zaproxy/zaproxy:stable zap-api-scan.py \
    -t https://target.com/api/openapi.json \
    -f openapi \
    -r report.html
```

## 🎬 Παραδείγματα σεναρίων ελέγχου

### Παράδειγμα 1: Σύντομη σάρωση ιστοτόπου
```
1. Εισαγάγετε το URL στην καρτέλα Quick Start
2. Πατήστε "Attack" για εκκίνηση της διαδικασίας ελέγχου
3. Το ZAP θα εκτελέσει αυτόματη εξερεύνηση και σάρωση
4. Εξετάστε τις ειδοποιήσεις μετά την ολοκλήρωση
```

### Παράδειγμα 2: Συνδυασμός χειροκίνητων και αυτοματοποιημένων ελέγχων
```
1. Ρυθμίστε τον browser ώστε να χρησιμοποιεί τον proxy του ZAP
2. Εξερευνήστε χειροκίνητα τις λειτουργίες της εφαρμογής
3. Δεξί κλικ στον στόχο μέσα στο Sites → Spider
4. Περιμένετε να ολοκληρωθεί το Spider
5. Δεξί κλικ στον στόχο → Active Scan
6. Εξετάστε τις ειδοποιήσεις
7. Δημιουργία αναφοράς
```

### Παράδειγμα 3: Σάρωση με ταυτοποίηση
```
1. Δημιουργήστε Context για τον στόχο
2. Ρυθμίστε ταυτοποίηση μέσω φόρμας (Form-based Authentication)
3. Προσθέστε στοιχεία εργαστηριακού χρήστη
4. Ρυθμίστε το forced user mode για χρήση συγκεκριμένου χρήστη
5. Εκτελέστε το Spider με τον ταυτοποιημένο χρήστη
6. Active Scan — ενεργός έλεγχος
```

### Παράδειγμα 4: Έλεγχος API
```
1. Εισαγάγετε τον ορισμό API σε μορφή OpenAPI/Swagger
2. Μενού: File → Import → Import OpenAPI definition (εισαγωγή ορισμού API)
3. Εξερευνήστε τις διαδρομές του API, με βάση και τον εισαγόμενο ορισμό του
4. Active Scan — ενεργός έλεγχος
```
